# 任务看板管理系统资料整理

开始日期：2026-11-08。

当前阶段：`task-board-requirements-v1.0-review` 本地资料已整理，待整体复核；尚未启动本案例生成或验收。包括 12 个需求/权限/验收模块、两个项目的具体样例、两张图片与 84 项未执行验收。

交付原则：用户明确本次按完整系统整理，不预设首版、MVP 或后续阶段；实际发现遗漏再补充。已明确排除项和可选项继续按各自决定保留，历史决策中的首版措辞不再代表分阶段计划。

## 已确认的起点

- 以任务看板管理系统作为 AI App 资料包案例。
- 先在本地整理完整、完善的需求和资料，再交给 Kooboo AI 生成。
- 逐模块讨论，并保留决策过程与最终产物，供其他系统参照、学习和优化。
- 支持多个项目，每个项目有独立看板与成员。
- 项目内设管理员和成员，不提供只读访客。
- 项目及任务仅项目成员可见，由项目管理员添加成员。
- 所有登录用户均可创建项目，创建者自动成为该项目管理员。
- 用户身份与账号维护复用 Kooboo 已有账号体系，不自建应用账号密码；项目成员关系和项目内角色仍独立维护。
- 项目名称必填、描述选填，由项目管理员修改。
- 同一用户可加入多个项目，各项目身份独立。
- 管理员从系统已有用户中添加成员，默认加入为成员。
- 项目可有多名管理员，至少保留一名；最后一名不能直接退出或被移除。
- 普通成员可主动退出，管理员可移除成员、提升成员或降级及移除其他管理员；始终保留至少一名管理员。
- 退出或被移除后立即失去项目访问权；已创建任务与历史保留，人员标识为“已离开项目”。
- 归档按可恢复的软删除处理；项目管理员可以归档和恢复，归档保留数据，项目信息、看板和任务只读。
- 提供项目真删除，仅该项目管理员可以执行；真删除后不提供应用内恢复。
- 进行中和已归档项目均可直接删除，展示范围并输入项目名称确认；一并删除项目、看板、任务、成员关系与项目内历史，保留用户账号和其他项目数据。
- 每项目一个看板，随项目自动建立，初始列为待办、进行中、已完成。
- 列直接表示任务状态；项目管理员可维护列结构，每列可设置颜色用于区分。
- 管理员只能删除空列；管理员和成员均可通过拖拽或详情切换本项目任意任务的状态，允许跳转、回退和重新打开。
- 任务状态变化记录操作人、时间、具体任务和前后状态，两种操作入口均记录。
- 管理员指定默认列和完成列，初始分别为待办、已完成；两者不同，至少保留两列，删除前须指定替代列且清空原列。
- 完成含义不随列改名或排序改变；同列支持拖拽排序，跨列移动默认进入目标列末尾。
- 进入完成列时记录本次完成时间，直接创建为完成状态也记录；重新打开后清空当前完成时间并保留历史，再次完成时记录新时间。
- 更换完成列要求原完成列与新完成列均为空，且继续遵守默认列与完成列不同的约束。
- 任务标题必填，描述选填；最多一名当前项目成员作为负责人，也可不分配；优先级为低、普通、高、紧急，默认普通；截止时间选填，填写日期、具体时间与明确时区。
- 支持用户自定义标签，作为独立筛选维度，不参与看板列排布。
- 标签在项目内共用，每条任务可有多个标签；管理员和成员均可创建，管理员可重命名、删除，删除只移除标签关联。
- 任务与评论取消独立附件功能，正文支持图片；本地图片先上传取得链接再插入，持久化 Markdown 不保存 Base64 或 data URL。
- 正文图片遵守项目成员访问范围，项目或任务归档后正文只读，图片仍可按权限查看。
- 管理员和成员均可创建、编辑本项目任意任务，应用或移除标签，以及指定、更换或清空负责人；归档项目仍只读。
- 系统自动记录任务创建人、创建时间及最后更新时间，用户不能手动修改。
- 完成与归档独立；管理员和成员均可归档、恢复任意任务，归档后收起并只读，保留状态、完成时间、负责人、正文图片、评论和历史。
- 进行中项目内，仅管理员可二次确认后真删除未归档或已归档任务、评论及任务内历史；保留共用标签和其他任务，图片按有效引用清理。
- 成员离开时，进行中项目内未归档且未完成任务自动清空负责人；已完成或只读任务保留原负责人，恢复可编辑时检查并清空仍已离开的未完成任务负责人。
- 重新加入默认成员身份，不自动恢复原管理员身份或此前已清空、已转交的任务；分配变更及自动清空均留日志。
- 归档任务默认隐藏，但仍保留所属状态列；判断能否删除列时计入归档任务，不能因看板暂时无可见卡片就直接删除。
- 更换完成列时原、新两列均不能有归档任务；恢复任务放回原列末尾，新建任务放到所选列末尾。
- 恢复项目保留任务各自的归档标记，不自动恢复单独归档的任务。
- 任务描述与评论正文支持 Markdown 及正文图片；评论按时间排列，不能为空；纯图片评论至少包含一张上传成功、取得链接并插入正文的图片，空白或上传占位图不算有效内容。
- 所有项目成员可查看发送评论；正文仅作者可编辑，作者和管理员可删除，归档后只读；不做子任务层级和跨项目移动。
- Markdown 支持常用语法与源码/预览切换，编辑和渲染优先复用第三方库，具体选型留到生成实现阶段适配 Kooboo。
- 截止及事件时间统一 UTC 保存，按用户时区显示；超过截止时刻且未完成即逾期，各成员结果一致，完成不显示、重新打开重新判断。不要求项目业务时区，撤销按日逾期方案。
- 已完成任务重新打开时，原负责人若仍已离开项目，则自动清空，同时记录状态及分配变化。
- 项目任务提供看板与列表切换；当前项目关键词搜索覆盖标题和描述，不搜索评论正文。
- 基础筛选支持状态、负责人（含未分配）、优先级、标签、截止时间及是否逾期；不同条件同时满足，同条件多选及多标签按任一匹配。
- 搜索按标题或描述包含关键词匹配、忽略英文大小写，不匹配 Markdown 标记及图片地址；归档任务在项目内主动进入的归档列表查询。
- 列表默认最新创建在前，可按截止时间或优先级排序；手动模式的顺序在项目内共享并持久保存，与看板顺序分别保存，字段排序不覆盖手动顺序，筛选期间暂停列表拖拽。
- 不提供跨项目“我的任务”汇总；项目内“仅看我的任务”为必做，按当前登录用户为负责人筛选，看板和列表均支持。
- 操作记录覆盖任务、评论及项目管理；描述只记修改事件，评论日志不备份全文图片；成员可查看倒序记录，不能单独修改或删除，不记录浏览、搜索与拖拽排序。
- 真删除任务清除任务内历史，项目记录保留任务标识、当时标题、删除人及时间；真删除整个项目时一起清除。
- 必须支持站内通知、邮件通知和 @提及；描述及评论可搜索选择当前成员，保存后通知，编辑仅新增提及通知，同次接收去重且排除操作者。
- 操作失败保留输入、拖拽失败恢复位置，避免重复提交；并发修改提示刷新核对，提交时重新校验权限及归档、删除状态。
- 正文图片支持选择、粘贴、拖入，先上传转链接再保存；支持 JPG、PNG、WebP、GIF，单张不超过 10 MB，点击可放大预览；按有效引用清理，归档不删图。
- 使用真实服务端存储，刷新重启数据保留，交付源码、配置、初始化及备份恢复说明；样例和验收需覆盖多项目、多角色及实际通知，邮件须验证收件。
- 任务编号采用 `#0001` 格式，编辑、归档恢复不变、删除不复用；编号全应用递增及最少四位是单列的整理默认，未伪装为用户逐项决定。
- 任务列表点击任务行或标题打开详情抽屉（drawer），其中提供字段、Markdown 描述、评论与操作记录，归档只读，桌面及手机均可使用。
