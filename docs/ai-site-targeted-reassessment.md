# AI Site 模板：程序核验与针对性复评

更新：2026-11-10。本文描述本次源码实现，不表示已部署到本机4180。没有恢复已停止的生成站，也没有请求真实模型评测。

## 目标与分工

目标是在保持验收标准的前提下，让程序承担确定性核验，让AI集中判断原问题、变化的页面和无法由程序判定的内容。预算停止不能代替合格交付，本次没有新增评测预算熔断。

| 程序负责 | AI负责 |
| --- | --- |
| 冻结路径和查询参数映射、双端取证与覆盖、HTTP状态、稳定状态、证据字节和所属修订 | 视觉构图、字体、间距、层级、正文语义和参考对应 |
| 明确存储契约下的分页全集、数量、完整标识、缺少/多余记录及必填字段非空 | 动态模板使用是否正确、数据语义、关系与业务行为 |
| 批次输入、图片连续切片、结果结构与引用校验、加权汇总、问题ID闭环 | 针对性实际交互及操作前后效果，无法验证就保留未验证 |

HTTP成功、截图存在、数量相等、字段非空都不能自动变成语义、视觉或交互通过。

## 一次初评

1. 使用固定输入、规则与交付清单，由程序采集声明路径和模板样本的双端证据；来源证据在同一工作流的冻结快照内复用。
2. 程序生成 `template-program.json`。页面项给出每个路径/视口的截图、观察、HTTP与稳定状态；数据项仅在有明确 `records` 契约时读取目标全集并对账。
3. 程序为每个独立批次准备相关图片、连续切片、事实摘要与结果骨架。AI核实本批语义、视觉和必要交互，不重复其他批次或程序已完成的全量计数。
4. 宿主注入真实数量、全部标识与页面覆盖事实。程序发现缺失、非成功HTTP或未完成取证时可以降低模型的通过判断，不能提升未知判断。
5. 每批保存经过校验的检查点，最后按原全部指标、路径、双端和交付要求验证汇总。

数据契约例：

```json
{
  "records": {
    "storage": "sqlite",
    "container": "Cars",
    "keyField": "SourceUrl",
    "requiredFields": ["Name"]
  }
}
```

该声明只适用于已核实的真实表和字段，`SourceUrl` 的值必须精确对应来源 `expectedKeys`。支持SQLite单元格列表、内容 `textValues` 和商品分页的实际返回契约。内容集合使用明确FolderId。历史清单不会按标题自动猜存储；没有可信映射、来源总量或全部标识时仍须独立核实。关系和素材计量域不套用普通记录计数。

程序读取窗口为100页、10000条；超过窗口、元数据不一致、未知响应形状、重复标识或取消都保留未验证，不截断后宣布完成。此窗口是程序取证边界，不是费用熔断或全集通过依据。

## 修复后的一次复评

1. **定位基线。** 修复任务持久关联原报告，手动补评使用其父评测报告。基线必须属于同一工作流、站点、输入、环境、范围与规则；不兼容时使用初评流程。自动修复仍遵守原有图片与改善分析的委托要求。
2. **采集当前证据。** 不把旧目标图片改名当新证据。程序核对旧文件完整性，比较当前截图字节、URL、视口、文字/框架观察和稳定状态；实现证据需要重新读取当前后台，比较实际结果。
3. **只继承有依据的已通过判断。** 原评分未通过、低于目标、缺少证据或完整度未验证时继续独立复验。交互和业务流程不会仅凭静态相等自动继承。静态页面条目可以按路径拆分：某一路径变化不要求AI重新检查同条目内全部其他路径；共享的非图像依赖变化仍会扩大范围。
4. **逐项复验原问题。** 每个原问题/未验证项有稳定ID，必须恰好一次返回“已解决、仍存在、未验证”、原因和证据。路径、query、视口或后台请求不对应时不能关闭问题；有原交互证据的项还要求当前实际操作记录。没有可追溯定位的历史问题保留未验证，不能拿任意截图关闭。
5. **关联回归。** 程序不能证明不变的评分和交付项进入本轮AI批次。新增缺陷另行记录，不重复发起全站探索或重新盘点同一来源。
6. **完整验收。** 合并独立复验与当前证据一致后继承的判断，重新执行原完整范围的校验和总分计算。仍存在的问题保留原严重程度，未验证项阻止宣称完成；旧标题消失不是已解决的证据。

只读缓存限定在AI Site模板评测。相同任务/修订/站点身份和请求、且文件哈希完整时才能复用；参数校验不会被缓存绕过。浏览器操作后，相关数据读取缓存失效，最终汇总前再核对程序事实。恢复时所有批次重新校验证据；清单扩展后重新准备范围。

报告显示基线、继承评分/交付项与路径、本轮独立审查范围，以及原问题逐项复验明细。历史报告保持原样，不回填伪造的复验结果。

## 当前边界与后续

- 本版仍由程序按清单采集当前全范围目标截图，以确认哪些判断可继承；减少的是AI重复审查。尚未建立可靠的代码变更到页面/组件依赖图，不声称已经做到只截变更局部。
- 字节完全一致是保守条件。轮播、动态时间、随机内容或细微像素变化可能扩大独立复验范围；没有稳定依赖证据时不做宽松复用。
- AI仍使用Codex SDK完成独立短批次，尚未改造成每个语义判断一次模型请求。经验选择、长指导、语义检查中的工具往返和重复故障学习仍需进一步压缩。
- 来源全集未知不因目标站修复而消失。新来源证据可通过正常清单扩展核实；缺乏定位或无法核实的历史缺口不会被自动宣布解决。来源限制与目标缺陷的修复调度仍需后续进一步区分。
- 此实现只改变模板分支；采集迁移的程序核验与AI App流程保持各自原有契约。

模拟端到端样本中，初评3个AI批次；修复后当前证据一致、仅有一个旧问题时缩为1批，完整报告仍含双端评分和完整度，恢复时不重复模型审查。这只证明范围缩小与检查点行为，不代表真实模型请求数、token、费用或耗时已经按相同比例下降。真实收益需在另行安排的受控样本中验证。
