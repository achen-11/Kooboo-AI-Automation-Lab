# 耗时与成本 Dashboard

入口：`/#/dashboard`。目标是比较一次生成、一次评测或完整流程的投入，定位阶段消耗，并能从异常点进入对应任务。默认 AI Site 模板、近 7 个北京时间自然日，不增加流程版本标识。

## 页面

- 全站概览：资源、去重生成站、累计完整流程、运行和排队任务数，不受日期、场景和范围筛选影响。
- 时段筛选：今日、昨日、近 7 天、近 30 天、自定义到分钟；小时或自然日粒度；场景、首页/全站范围。
- 时段消耗：按阶段堆叠的费用/累计执行时间，排队单列。可点击柱形或数据表进一步选择对应时段。
- 任务效率：选择一次评测、一次生成、完整流程；按开始时间归组，显示完整任务的阶段均值和单次任务散点。完整费用和执行时间使用各自数据完整的样本，分别显示样本数。
- 自定义对比时段：默认前一个等长时段，可修改到小时/分钟。展示均值、变化、样本数、完成和进行中数量。基准无样本或为零时不算百分比，不自动推断变化原因。
- 分页任务明细：时间、状态、费用、执行时间、原有评测结论；展开阶段分布，进入原任务。每页 20 条。

## 时间与费用口径

查询时间区间为 `[start,end)`，固定北京时间。按小时最多 31 天，按日及对比时段最多 93 天。日期区间未结束时数据仍会累计。

**时段消耗**回答“这段时间消耗了多少”：费用依据请求开始时间分桶，不按分钟摊算费用；执行区间按实际重叠时间拆入各桶。每个任务内优先归属内嵌阶段，避免重复计算；不同任务的执行时间允许相加，因此一小时内可能累计执行数小时。运行区间至最后可信心跳，排队区间可计至当前时刻。

累计执行时间只有在时段内涉及的任务均具备完整阶段计时时才显示为总量；否则 `executionMs` 为 null，页面显示“未完整记录”，并保留已记录时长及完整计时任务数。覆盖范围包含时段内的阶段执行、请求发生及跨入时段的已知请求区间，也包含时段内已开始或已结束但缺失计时的任务。排队不充当执行记录；历史请求耗时不补算为阶段耗时。耗时图仍展示已记录区间，并标明计时不全的任务数。

**任务效率**回答“这段时间开始的一次任务，总共需要多少投入”：生成/评测按首次已记录非排队阶段开始时间归组，完整流程按根任务发起时间归组。一次 11:50–12:30 的评测，在实际消耗中分为 10 分钟和 30 分钟，在效率中只对 11 点这一组贡献一次完整的 40 分钟。后续完成后，均值回填其开始的时段，不归入结束时段。

执行时间为排队以外各阶段记录之和，包含已有记录的后台整理；开始到结束的跨度另行展示，不与并行任务累计执行时间混淆。费用包含该任务或流程的后续后台请求，后台整理可能使费用继续更新。

仅已完成且对应数据完整的任务参与均值。失败、中断、停止的消耗计入实际消耗与明细，进行中和排队数始终展示。没有开始时间的历史任务仅按创建时间选入明细，不参加阶段效率均值和小时趋势；不从 updatedAt、自然语言日志或模型请求区间虚构完整执行时间。

自动评测由持久的 evaluationTaskId、workflowIds、optimizationRootId 归入原流程。仅有 parentId 的手动评测不自动合并；独立继续生成另算流程。修复生成和优化分析合并展示为修复阶段。评测结论不等同于交付验收；缺失或范围、修订不匹配的报告不提升为通过。

## 实现与验证边界

新增 `GET /api/automation/dashboard/analytics` 接口；旧 `/dashboard?days=...` 接口保留兼容。响应只包含紧凑统计与分页明细，不含原始 usage、模型端点、凭证、任务正文或图片。计时按任务分批读取，费用按紧凑 SQL 投影归集。

ECharts 6.1.0 独立按需加载。阶段固定配色，日期横排，图例可切换；图表自适应容器并在卸载时释放。数据表提供图表之外的键盘操作入口。隐藏页面暂停轮询，过滤变化取消旧请求，保留全站概览。

筛选请求期间保留现有面板和图表实例。切换效率单位仅更新效率与任务明细，切换对比仅更新对比结果，分页不重画图表；失败保留上次成功内容。连续切换仍校验最新请求及数据所属筛选，避免对比请求覆盖尚未完成的单位切换。

针对性测试覆盖跨小时、跨时段长任务、进行中/失败/中断、嵌套阶段、自动与手动流程归属、分钟边界、未知费用和历史缺失、分页与过滤、API 参数及响应边界。Vue 自定义渲染器测试实际组件的筛选/跳转/过期请求处理，ECharts 使用无浏览器 SVG 渲染验证实际图表配置；这些检查不代表浏览器视觉验收。
