# 模块六：操作记录、通知与异常处理

状态：通知及 @提及细则均已确认（D117、D118），按完整交付整理；下文保留过程中的待确认状态供追溯，现行正式需求见 [操作记录、通知与异常处理](../package/06-history-and-exceptions.md)。

## 已确认的前提

- 状态与分配实际变更均留日志，包含操作人、时间、任务及前后值；自动清空注明原因及触发人。
- 失败、取消或未改变状态不能冒充成功的状态变更日志。
- 退出或被移除后立即失去项目访问权；原历史保留并标记人员已离开。
- 归档任务保留历史且只读；真删除任务删除任务内历史，真删除项目删除项目内历史。
- 项目或任务归档后评论只读，不能发送、编辑或删除。
- 本轮确认项目级记录、评论变更日志及并发处理；通知必须支持站内通知和邮件通知，细则继续收口。

## 已确认的整组规则

用户回复“可以按建议, 但是通知要改变一下, 我们要支持站点通知和邮件通知”。除通知外按原建议确认，通知改为必须支持站内通知和邮件通知，记为 D095—D102，已同步正式需求。这里将“站点通知”按应用内站内通知理解，具体入口和行为仍待确认。

| 主题 | 已确认规则 |
| --- | --- |
| 任务记录 | 记录创建、字段修改、状态及负责人变化、标签调整、归档与恢复；字段包含标题、描述、优先级和截止日期。短字段记录前后值，描述仅记录“修改了描述”，首版不做正文版本历史 |
| 评论记录 | 新增、编辑、删除评论均留操作记录；记录谁在何时执行何种操作，不在日志中备份评论全文或图片；删除评论后其正文不通过历史重新展示 |
| 项目记录 | 记录项目信息、成员与角色、列与标签配置、项目归档恢复及任务真删除；任务真删除后在项目记录中保留任务标识、当时标题、删除人和时间，不保留任务正文；真删除整个项目时这些记录一起删除 |
| 展示与权限 | 任务详情展示该任务历史，项目内提供项目操作记录；按时间倒序，所有当前项目成员可查看，不能手动改写或单独删除记录；首版不记录浏览、搜索和拖拽排序 |
| 通知范围 | 首版必须支持站内通知及邮件通知；原“仅提示、不做通知”候选被用户修订，不再适用；具体触发与接收规则待确认 |
| 失败与重试 | 失败明确提示，保留未保存内容并允许重试；失败不显示成功、不写成功变更日志，拖拽失败恢复原位置，提交期间避免重复发送 |
| 同时修改 | 多人同时修改同一任务或评论，后提交方遇到内容已变化时提示刷新核对并保留输入，不直接覆盖他人更新 |
| 权限及归档变化 | 提交时再次检查权限与归档状态；已失去权限、已删除或已归档时拒绝不允许的操作，提示刷新；失去权限后停止展示项目数据 |

## 已确认：通知细则与范围修订

用户逐项回复“@提及也是要做的”“我们基本不分什么首版, 我们基本首版就是终版了, 除非有什么是的确没有想到的, 才会后面添加这样”“其他的按建议即可”。通知及图片细则按建议确认（D103—D113），@提及从原排除候选改为必做；不得继续以首版为由缩减功能，具体提及行为尚待确认。以下表格是修订后的当前规则，前文带首版的旧表格仅保留为历史过程。

| 主题 | 已确认规则 |
| --- | --- |
| 触发与接收人 | 任务分配或转交通知新旧负责人；状态变化及新增评论通知创建人和当前负责人；加入项目及角色变化通知相关本人；接收人去重，不通知本次操作者，任务通知仅发给当前仍有项目权限的人 |
| 站内通知 | 提供统一通知入口、未读数、单条及全部已读；点击进入关联项目或任务；失去权限后不再展示该项目通知内容，目标已删除时提示不可用，不暴露原正文 |
| 邮件通知 | 与上述事件对应，默认开启，用户可关闭邮件；邮箱来自用户账号；邮件仅含事件摘要、项目或任务名称及访问链接，不附正文和图片，打开链接仍需登录与项目权限；通知邮件已发出后不由应用撤回 |
| 发送与失败 | 业务保存成功后才产生通知；邮件异步发送、失败可重试并防止重复发送，不回滚已成功业务；未配置邮件或用户无邮箱时，站内通知仍正常，明确记录未发送原因；真实交付需配置发件服务并验证收件 |
| 功能边界 | @提及必做，具体细则待确认；定时到期催办、移动推送按其余建议排除，不将它们预设为后续阶段；普通字段、排序和评论编辑删除不触发常规通知，编辑时新增提及如何通知另行确认 |
