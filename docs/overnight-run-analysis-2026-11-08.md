## 结论与优先顺序

1. **先修交付事实与数据模型，再优化提示词。** manwei 的 483 条内容确实存在，但来源 756 条分类关系只保存 680 条；保存的分类模板又按标题去重，重算只显示 678 条。旧分页后缀直接被剥掉。HTTP 200、记录总数和 Preflight PASS 都无法发现这些交付缺口。
2. **把机器可判定的问题留给程序。** 清单兜底超长、证据角色/视口缺失、提交封装错误、失效线程和未知 usage，应有结构化校验与对应恢复动作。多轮 Agent 反复解释同一错误会增加请求和延迟，不能替代修复。
3. **经验应传递判断方法，当前来源决定具体做法。** oravix 采用了源自 rendani 的移动菜单经验，生成自述按“紧凑下拉”实现；oravix 独立报告却记录其参考站为全屏菜单。这是负迁移风险，不能用“采用过经验”证明交付改善。
4. **复盘失败不等于需要更大预算。** manwei 正式报告复盘在约 40 秒内搜索经验库 13 次，20 次模型请求用尽而未提交。rendani 的另一次复盘则经历上下文预算不足、502、提交封装错误，最后靠已有草稿重放校验恢复。两者根因不同。
5. **按站点合并成本，按范围和修订版本判断质量。** 六个站的 2,459 条请求记录中，已知 usage 按账本价格快照估算共 ¥16.73556216，另有 32 条无完整 usage。rendani 首页优化链累计 ¥5.59204896；继续补全全站后，同站累计 ¥7.35195116。首页曾达到 91.8 / 91，不能代表随后版本的全站交付通过。

## 请求、token 和时间浪费

缓存输入占各站已知 input 的约 97%–99%，因此“累计 input 很大”不能直接等价为昂贵的非缓存输入，也不能据此判定某个读取完全无价值。但缓存仍计入请求上下文、token 预算和传输/处理，不能当作免费无限重复。

要使用冻结策略而非文档默认值解释中断：M-G 的 planning 是 1,000,000 token / 20 请求 / 3 分钟；O-G、S-G 是 10,000,000 token / 200 请求 / 5 分钟；本次学习运行保存的策略为 50,000,000 token / 20 请求 / 3 分钟。`RequestBudget` 对输入按请求字节及图片估算预占，真实 usage 返回后核销，因此“剩余预算不能接收下一次上下文”可能在已知实际 token 尚未达到名义上限时触发。它不是官方 tokenizer 的精确余额，也不应通过无上限加预算掩盖上下文膨胀。

## 迁移交付门槛：应固化为契约

1. **来源范围**：固定输入版本、入口语言、抓取时间和原始证据哈希；记录导航、站点地图、列表分页、详情、附件、孤立入口线索和失败 URL。来源不完整时保持 sourceComplete=false，用户确认的有限迁移范围另行版本化，不能只把任务标 completed。
2. **实体与分类关系**：分别校验唯一实体 ID、分类 ID、多对多关系键、每分类数量与孤儿/悬空引用。预期集合减实际集合必须为空；还应检查额外项，不能只用实际数量 >= 预期数量。标题仅是可变字段。
3. **分页与旧 URL**：保存每个旧页的页码、实体顺序/集合、目标 URL、状态及重定向链。首页/中间页/末页、空页和非法页码都要核对；重复第一页返回 200 必须失败。不能只按分类基路径去重。
4. **标题与内容**：拆开正文名称/H1、浏览器/服务端 title、分类标签、description、canonical、语言与面包屑字段；校验正文/图片/链接和必要富文本顺序。正文转换须披露并获得范围授权，不能静默改成“后续优化”。
5. **SEO 与环境**：迁移按旧 URL 映射、真实 404/重定向、服务端元数据及正式域名上线证据审查；预览环境缺上线证据保留未验证。模板仅使用适用的元数据/发布准备要求，不能自动要求旧域名权重迁移。
6. **双端与动态模板**：全量数据/关系核对和模板视觉抽样分别呈现。静态页面全路径双端证据；动态模板按冻结代表样本和边界样本检查 desktop/mobile。长正文、表格/大图、多归属、最大分类、首末分页、空内容、未知 ID 应进入样本，不以首页截图代替内页。
7. **业务交付**：前端 success 文案、演示表单、mailto 和真实存储/投递分别标记；没有授权或来源不能提交真实业务。必交付项 missing/partial 阻止通过，来源或必要证据未知阻止“全站完成”；UI 高分不覆盖这些状态。

当前 `validateCompleteness` 对已验证 data 主要检查数量下限及 expectedKeys 是否被包含；对 observedKeys 的额外项、关系语义、页码和标题真实性仍需更明确的数据模型。不可通过让评测模型随意改预期值来满足检查。

## 后续验证设计与停止条件（提案）

先用本次已保存证据做离线回放，处理 P0 的确定性问题，不需要新模型或新站。完成后若用户另行授权付费验证，可选一条小型迁移和一条有集合的模板，固定资料、规则、模型、价格快照、目标范围与费用上限；对照更改前后的同类流程。

主要指标是每站累计已知费用与未知比例、从入队到有效报告的墙钟/活动耗时、有效模型请求数、完整度必交付缺项、独立报告质量和人工介入次数。辅助指标包括重复读取、无新增检索、schema 修正、恢复次数与证据复用率。不能只优化 token 数或首页分数，也不能将整体改善分摊给每条经验。

若出现来源未闭合、同一确定性错误重复、未知 usage、证据修订不匹配、必交付缺失或预算不足，则按对应停止原因保留现场；不自动抬高预算、不缩减既定交付范围、不以旧高分结束新版本任务。
