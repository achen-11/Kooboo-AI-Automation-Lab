# 采集与 A 段复核 SOP v1

1. 平台固定已授权任务来源、范围、输入版本与执行策略；调用内置 JSON bridge，不拼 shell、不选择任意目录、不安装依赖。新自动操作遵循队列启用状态。
2. 程序分批 plan→discover→fetch→extract→assets→data→render→verify。读取短摘要、检查点和产物索引，按需分页取全；不得以工具输出截断缩减范围。
3. A1核范围与排除依据；A2对导航、页脚、sitemap、列表和交互入口；A3对来源声明总数/总页数/身份/分类关系与实际记录。总量无依据时保持未知，不伪造百分比。
4. A4区分 HTTP 解码前响应 body、保存 HTML、渲染 DOM；核状态、跳转、编码、错误页和空壳。A5按页面类型对照原件、fullText、blocks、逐页内容、字段、规格表、隐藏区域及候选裁剪。候选记录不得作为唯一迁移正文。
5. A6核图片/附件计划、下载文件、类型及实际引用；PDF保留不等于正文已提取，图片保留不等于OCR。核心内容依赖未实现提取能力时保留缺口。
6. 可配置问题先组织有限规则候选，以失败页、正常页、模板变体和保留回归样本做独立试跑。固定预期由平台保留，修复候选不得更改它。只采用当前任务中哈希绑定、原件未变、有效固定预期通过的版本；重处理受影响项并重核。匹配冲突和未知模板不得静默排除。
7. 配置解决不了的能力缺口形成隔离代码修复目标。隔离未实际验证时不自动运行任意代码；工作目录隔离或静态扫描不等于网络/进程/凭证边界落实。
8. A7将资料、来源清单、证据、规则和独立复核固定为共同版本。verify退出0、no-known-gaps、样本通过、文件数齐全与AI自述均不能独立放行。引擎报告保持 sourceCoverage未知、scopeCoverage未验证，平台只按实际证据作范围结论。
9. 有可修缺口则给出对象、依据、验收方法、下一步和影响范围；暂时故障保留成功对象与恢复点；结果不明先核对进程/回执，不盲目重复写入。取消、明确硬限制和防循环策略继续适用。
10. 交接 B 段只使用已冻结并通过 A 段条件的资料版本；B 段发现来源缺口则回 A 段形成新资料版本，旧报告及原件保持可追溯。

浏览器沿用单独明确授权；本 SOP 不自动获得浏览器操作、登录、验证码绕过或生产发布权限。
