# 项目信息与成员管理

状态：业务规则已整理；名称校验采用 D125，成员并发及自行降级补充采用整理默认 R02，供整体复核。

## 项目基本信息

- 项目名称必填。
- 项目描述选填。
- 由项目管理员修改项目基本信息。

项目名称去除首尾空白后不能为空，允许与其他项目同名，各项目身份独立；技术长度上限由实现合理设置并提示，详见 [字段规则](10-fields-and-ui.md)。

## 项目成员与身份

- 同一用户可加入多个项目，各项目身份独立管理。
- 同一用户可以在项目 A 担任管理员、在项目 B 担任成员。在一个项目的身份不自动赋予其他项目的访问权或管理权。
- 项目管理员从系统已有用户中选择并添加成员，新增身份默认为成员。
- 系统已有用户来自 Kooboo 已有账号体系，登录与账号维护复用平台能力；项目身份独立于平台账号，不另建应用账号体系。

## 管理员保留要求

- 一个项目可以有多名管理员。
- 每个项目至少保留一名管理员。
- 最后一名管理员不能直接退出或被移除。

## 身份调整与交接

- 项目管理员可以将项目成员提升为管理员。
- 项目管理员可以降级或移除其他管理员。
- 所有身份变更都必须保留至少一名项目管理员。
- 最后一名管理员需要先安排另一名管理员，才能退出或被移除。

## 成员离开

- 普通成员可以主动退出项目。
- 项目管理员可以移除项目成员。
- 退出或被移除后，该用户立即失去该项目及任务的访问权。
- 成员离开不改变其在其他项目的身份与访问权。

## 离开后的任务与历史

- 保留离开成员已创建的任务和历史记录。
- 原人员信息标识为“已离开项目”。
- 进行中项目内，离开成员负责的未归档且未完成任务自动清空负责人；已完成任务保留原负责人并标记已离开项目。
- 项目或任务已归档时保留原负责人；恢复为可编辑时，未完成任务的负责人若仍已离开则自动清空。
- 手动及自动分配变化均记录时间、任务、前后负责人和操作人，自动处理注明原因；具体规则见 [任务模块](04-tasks-and-collaboration.md)。
- 本节规定成员离开时的数据保留；删除整个项目时按下文真删除范围处理。

## 成员重新加入

- 由项目管理员重新添加，默认身份为成员，不自动恢复原管理员身份。
- 不自动恢复此前已清空或已重新分配的任务。
- 重新加入不改写过去的退出和分配日志。

## 项目归档与恢复

- 项目有进行中和已归档两种状态，新建项目默认为进行中。
- 项目管理员可以归档项目；有未完成任务也可以归档，任务状态保留。
- 归档按软删除理解：保留项目数据和成员关系，从默认列表收起，项目成员可以在归档列表查看。
- 归档后的项目信息、看板和任务只读；成员管理和主动退出仍可操作。
- 归档期间继续遵守仅项目成员可见和至少保留一名管理员的要求。
- 项目管理员可以恢复归档项目；恢复后重新允许正常操作。
- 恢复项目保留各任务原有归档标记，单独归档的任务不会自动恢复，继续隐藏并只读；恢复可编辑的任务按成员离开规则检查负责人。

## 项目真删除

- 系统提供项目真删除能力。
- 仅该项目的管理员有权执行删除。
- 真删除后项目不再存在，不提供应用内恢复。
- 至少保留一名管理员的要求适用于仍存在的项目，不阻止项目管理员删除整个项目。
- 进行中和已归档项目均可直接删除，不要求先归档。
- 删除范围包括项目、看板、任务、项目成员关系和项目内历史。
- 删除项目不删除用户账号，不影响其他项目的数据和成员关系。
- 删除前展示关联数据范围及不可恢复的含义，输入项目名称确认后执行；未完成名称确认或取消时不执行删除。
- 任务与评论不提供独立附件；删除项目时其任务、评论随项目清除，不再被有效内容使用的正文图片按 [资源规则](07-images-and-resources.md) 清理，不误删其他有效内容仍在使用的图片。

## 可观察的预期结果

以下为已确认规则的验收表达，不扩展功能范围：

- 创建或修改项目时不能缺少项目名称；描述可以不填。
- 具有项目管理员身份的用户可以修改项目基本信息，普通成员不能执行此修改。
- 同一用户在两个项目的身份可以不同；修改其中一个项目的身份不改变另一个项目的身份。
- 从已有用户添加项目成员后，该用户默认具有该项目的成员身份。
- 允许一个项目存在多名管理员；尝试直接退出或移除最后一名管理员时应拒绝该操作，并保留其管理员身份。
- 管理员可以提升成员、降级或移除其他管理员；会使项目失去最后一名管理员的变更应被拒绝。
- 成员退出或被移除后，即使仍登录系统或持有直达链接，也不能继续访问该项目与任务。
- 成员离开后，其已创建任务和历史仍存在，人员信息显示“已离开项目”；其他项目的访问不受影响。
- 离开成员在进行中项目内的未归档且未完成任务变为未分配；已完成或归档任务保留原负责人，恢复为可编辑时按任务模块规则检查并清空仍已离开的未完成任务负责人。
- 成员重新加入后为成员身份，不自动恢复原管理员身份或重新认领已清空、已转交的任务。
- 管理员归档项目后，项目从默认列表收起，成员可在归档列表查看；数据与任务状态保留，项目信息、看板和任务不能修改。
- 项目管理员恢复归档项目后，重新允许正常操作；归档期间成员访问和管理员保留约束仍生效。
- 恢复项目后，原本单独归档的任务仍保持归档，不因项目恢复而重新出现在常规看板或允许编辑。
- 普通成员和非成员不能删除项目；项目管理员执行真删除后项目不再存在，不能通过恢复归档功能找回。
- 管理员可对进行中或已归档项目发起删除；未完成项目名称确认或取消时项目及数据保留。
- 删除完成后，该项目的看板、任务、成员关系和项目内历史均被移除，用户账号与其他项目的数据和成员关系保留。

## 校验与并发补充

- 按整理默认 R02，存在其他管理员时允许自行降级；完成后立即按成员权限显示，失去管理入口。
- 重复添加不创建重复成员关系；并发降级、退出或移除也不能使管理员数变为零，过期请求提示最新状态。
- 修改与删除失败不显示成功，不产生成功日志，保留可重试输入；提交时重新校验权限、归档与删除状态，详见 [异常处理](06-history-and-exceptions.md)。

对应决策：D007—D020；成员离开与再加入的任务联动见 D058—D061，恢复项目保留任务归档标记见 D065（见资料包之外的整理记录）。
