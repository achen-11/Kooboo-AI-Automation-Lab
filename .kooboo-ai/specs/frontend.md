The sidebar exposes “耗时与成本” at `/dashboard`. Default to AI Site templates and 7 Beijing calendar days. Global resource/site/workflow/running/queued counts stay independent of filters. Offer today, yesterday, 7/30 days and custom minute-precision ranges, hourly/daily buckets, scope and scenario filters. Separate actual-period consumption (request-time charges and clipped execution intervals) from complete task efficiency grouped by execution start; workflow cohorts use the root creation time. Keep old dashboard API compatible. Do not add process-version markers. API projections exclude credentials, raw usage and task conversations. See docs/dashboard-analytics.md for boundaries.

The active application is Vue 3 + Vite with an independent Node.js server. The SPA uses hash routing and root entry `/`; source lives in `frontend/src/` and shared application types live in `shared/`.

`npm run dev` starts the Node API and background worker at `http://127.0.0.1:4180`. For frontend hot reload, run `npm run dev:web` separately; Vite listens on `http://127.0.0.1:4181` and proxies `/api` to the Node server.

`npm run build` writes frontend assets into `dist/` and compiles readable Node modules into `dist-server/`. `npm start` serves the SPA and API together. Former Kooboo runtime resources have been removed; the old implementation is available in Git history.

The API starts and supervises a separate background process for both task engines. Synchronous evidence hashing, HTML parsing and verification must not share the HTTP event loop. SQLite WAL and encrypted settings remain shared; IPC carries cancellation, ownership and lifecycle messages only. `/api/health` exposes `workerReady` so an exited executor is observable. Preserve durable cancellation and conservative recovery of uncertain requests when crossing process boundaries.

Keep the existing page layout, task stages, execution history, screenshot comparison, and site-preview iframe. The frontend establishes the HttpOnly local session automatically through `POST /api/login` when a request receives 401, shares concurrent connection attempts and retries each request at most once. There is no manual entry screen or logout control. Local session checks and trusted-origin restrictions remain in the backend; this is not production user authentication.

Settings include a single configurable image- and tool-capable Chat Completions model, Kooboo environments, review threshold, queue pause, a stage budget for each viewport capture and final scoring, and bounded capture attempts. Keep secret fields empty after saving and retain the existing secret unless explicitly replaced or cleared. Model tests submit actual pixels and validate function calls and tool result consumption.

The active backend is `server/`, contracts are `shared/`, evaluation instructions are `sop/`, and focused tests are `tests-node/`. The former `src/api/`, `src/code/`, `src/job/`, native binding types, and obsolete site publishing scripts are no longer part of the current tree. `kb push` is not part of the current development or deployment flow.

## Unified automation

The main sidebar pages are Resources, Tasks (default), Experiences, Rules, and Settings. Reports live in the generated site detail, under Evaluation results. They live under `frontend/src/views/automation/`. The sidebar persists collapsed state; icons use Lucide. `components/BaseSelect.vue` provides every visible selector, using typed `options` with `v-model`, compact/quiet/title variants and a custom popover menu. It supports search for long lists, disabled options, keyboard navigation, focus restoration and viewport-aware positioning, including inside native dialogs. Its hidden native select only preserves form submission and required-field validation; never expose a native select as the visual control. Resources use checkbox multi-selection for batch creation.

Experiences use a paginated library and a separate editable detail view with version history and explicit human disable protection. Settings expose Learning and Full-site Delivery policies. Keep adopted experience versions and the delivery manifest in task Input/configuration, learning runs in Execution, completeness checks in Evaluation results, and retained unknown request reservations in Usage. Reuse existing tabs, Disclosure, TablePagination and floating notifications. Learning failures do not invalidate a delivered report; full-site visual scores never stand in for verified completeness. See `docs/experience-learning-and-completeness.md` for budgets, API and validation boundaries.

The experience library uses compact segmented switches for enabled state, scenario and stage, each with an all option. On desktop, arrange search and enabled state on the first row, with scenario and stage groups side by side on the second; wrap as needed on narrow screens. Filter changes apply immediately and return to the first page; title search combines with these filters. Apply array-membership filters on the server before counting and paginating, and combine different filter dimensions with AND. Retain keyboard-operable buttons with explicit pressed states and a clear-filters action; distinguish no matches from an empty library.

New tasks use `/api/automation/` and are separate from legacy evaluation history, which remains accessible via `/legacy-evaluations`. New generation is driven by the existing Kooboo AI Chat frontend loop; evaluation uses Codex SDK with an isolated runtime home. The management tab does not own execution. See `docs/UNIFIED_AUTOMATION.md` for current validation boundaries.

Task execution settings keep “显示执行浏览器窗口” inside the initially collapsed Advanced disclosure under Local runtime. Default off means headless generation and AI followup; on enables visible browser sessions for diagnosis. Read this setting only when launching a new session, never replace an active browser or resend a prompt when it changes. Reuse the task profile and full Chromium in either mode. Evaluation stays headless. Saving uses the existing settings action and floating feedback; older clients omitting this field must retain its saved value.

Resource details use a compact two-row header: back navigation, identity and actions on the first row, section navigation and input-version metadata on the second. Long titles truncate with their full value available; narrow screens may wrap as needed. Keep the material content as the main use of the viewport.

The material browser is the main content surface, without a padded settings card around it. Available content/reference sites appear as compact links in its toolbar, showing both their role and actual address; truncate long addresses with the full URL available on hover. Merge identical links and omit missing-site placeholders. Description and external-source metadata are available through an optional, initially collapsed input-notes control, with a bounded scroll area when expanded. Do not reserve a description block for empty input. On desktop, the file hierarchy and preview use the remaining viewport height; narrow screens keep the stacked content layout.

Resource details show material inputs with a collapsible file hierarchy and a neighboring preview, stacking on narrow screens. Shared MaterialTree preserves logical package paths, sorts folders first, counts descendant files and supports upload removal without nesting buttons. File search reveals matching paths and ancestors without changing saved expansion state. MaterialBrowser initially selects README when available, loads only the selected file through the existing authenticated download endpoint and preserves an explicit download action. Common images including SVG render as image blobs with fit/original-size modes; text previews are limited to 256 KB with an explicit truncation notice. Markdown defaults to formatted reading through markdown-it with raw HTML disabled, with a source toggle; other text and code remain escaped plain text. Resolve relative document links against the current file and material package, select referenced files in place, and scroll document anchors without changing the SPA route. Local embedded images load through the authenticated file fetch only near the visible area and render as image blobs; remote images remain explicit external links. Unsupported formats remain downloadable. Cancel stale preview requests and release image object URLs on selection changes or unmount; do not execute uploaded HTML or embed SVG markup into the page.

Transient save/copy/import/publish feedback uses `lib/notifications.ts` and the single `components/MessageHost.vue` mounted in App. Messages float above the layout and expire automatically; persistent connection failures and form validation errors remain contextual. Settings model panels use an explicit vertical stack to separate fields, buttons and explanatory text.

The sidebar brand shows a separately clickable version button beneath the application name, with an update dot only after a successful check finds a newer release. Collapsed navigation retains an update icon; Settings opens the same SystemUpdateDialog. The dialog checks GitHub stable releases, shows version comparison and escaped release notes, and requires explicit confirmation before downloading/installing. Keep source credentials inside the collapsed update-source section, never in general settings responses. Closing the dialog does not cancel an accepted update. Poll persisted installation state and reconnect across restart; only announce success after the service version matches. Development checkouts can check releases but cannot install. Managed ZIP installs use the independent launcher, persistent maintenance gate and matching code/data backup; see docs/manual-updates.md for release and recovery boundaries.

Kooboo connections use account login as the main credential entry. A native modal collects username/password and, when requested, email/phone/authenticator verification code. Login verifies site-list access before saving only that connection and its encrypted token; passwords stay in the open form only and clear on close. Preserve other unsaved settings. Manual token input stays in a shared Disclosure. Cloud environment mismatches require an explicit address choice and a new login; never follow login redirects with credentials automatically. Migration delivery has no target-environment selector: the migration service returns the destination site identity and public URL for verification, without a target management connection.
