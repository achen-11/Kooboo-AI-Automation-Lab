# 全站完整度取证约定

清单规划 SOP 可以在“系统设置 → 全站交付”调整；评测 SOP 来自已发布规则快照。本文件说明主机校验的最低证据边界。

1. 从冻结输入、内容站、参考站和用户目标建立应交付清单。不得从生成站现有产物倒推全部范围。
2. 来源页、分页或记录集合未知时明确覆盖缺口，不宣布全站 100%。每项保留来源、期望、必交付条件、路径与视口。
3. 静态页面覆盖所有路径及 PC / 移动端。动态模板声明 `samples`，包含有理由选择的代表性 / 边界路径；每个样本分别检查双端画面。
4. 动态内容列出完整 `expectedKeys` 与 `expectedCount`，核对全部实际标识、数量、数据与 URL 对应。模板抽样不能代替全量数据核对。
5. 检查存储、路由、模板、动态取值，避免把每个产品静态建 Page。实现必须引用主机只读工具产生的 `implementation-*.json`，截图不足以证明。
6. 独立评测通过 `inspect.mjs` 复核来源，可按返回 schema 扩展清单；已有必交付范围不得删除、缩减或降级。按最新清单逐项提交 verified / partial / missing / unverified / excluded。
7. 引用真实证据文件。无法验证与缺失分别表达，保留视觉分数，不能通过提分掩盖必交付遗漏。预览环境与正式上线区分，SEO 技术检查不保证未来搜索表现。
8. 工具只有固定只读契约。产品分页是固定 POST 查询，不能向任意接口发起写入、执行 SQL / KScript 或修改目标站。
