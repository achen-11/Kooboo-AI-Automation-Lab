# 迁移清单方案评审

日期：2026-11-08。

评审依据：已通过 read_thread 读取「提炼会话经验」会话 `01a1b88d-c1d2-7461-90bd-c6ad908852d5` 的进一步讨论及用户确认，完整设计见 [迁移清单讨论](migration-manifest-discussion-2026-11-08.md)；对照当前 completeness、generator、optimization、followup、request-budget、worker 与共享契约。仅评审，不启动实现、模型或浏览器操作。

## 结论

方案可进入分批实施，覆盖了 manwei 已暴露的实体身份、分类关系、分页语义和宽泛修复委托等问题。与现有独立评测、版本隔离、可靠投递、预算和恢复方向一致。它是迁移自动化验收的前置工作；离线对账完成不代表站点修复或场景验收完成。

不需要重开总体产品设计；下述内容应作为实施约束与回归检查，部分已在方案中提出，评审明确其在现有代码中的影响范围。

## 必须覆盖的接入点

### 1. 结构化修复要贯通动作、证据和调度

当前 `followup.ts:30` 与 `optimization.ts:58` 强制修复引用图片，`generator.ts:128` 也只从正式报告读取修复图片；修复轮次的 sourceReportId 依赖正式报告。`advanceOptimization` 在 `optimization.ts:38` 创建独立评测，并在取得完整报告后才允许修复规划。

因此，仅增加 checklist 工具或放松 action schema 不足以支持“程序先发现关系/分页差异，直接安排数据修复”。应在同一条优化链中允许引用宿主保存的检查运行与结构化证据；视觉修复继续要求实际图片。鉴权、证据归属、目标版本、轮次、恢复、委托载体和报告入口需同步处理，不能制造假报告或附无关截图来满足旧契约。

### 2. 前置检查与质量修复共用有界流程

数据修复、视觉修复和混合修复均属于对同一目标站的实际修复，应纳入同一优化根任务的累计控制及串行互斥。检查批次、读取重试和结构修正另有限次，不能因为不计为修复轮次就不设上限。

当前 `optimization.ts:60` 依赖模型 progress.improved 更新无改善次数；接入 checklist 后应由宿主核对相同基线下已解决、剩余、新增和回归差异，AI 补充语义解释。不能通过分拆包、换阶段、清单升级或新建子任务重置计数及预算。

前置门槛以低成本确定性核对为主；不要求完整 UI 评测先通过才能进入独立 UI 评测。正式最终结论仍需独立证据。因限制停止时保存阶段核验结果与未评测项，不伪造当前正式评分，不借用旧版本分数。

### 3. 将来源覆盖和约定范围可核验分别落到契约

方案已正确区分有限范围来源闭合和整个源站覆盖。现有共享契约只有 sourceComplete，`validateCompleteness` 在其为 false 时将整体保留 unverified，`ensureManifest` 对已有 requirementsId 直接返回。

实施时应明确兼容行为：旧清单不自动升级为完整；诊断基线可以恢复补采，不能因为已有清单 ID 而永久跳过；用户明确限定范围后生成新基线并保留源站未知项。不能只检查 sourceComplete=true 就放行，也不能以缺少 sitemap 一概阻止建站。manwei 的来源缺口需要沿此流程真实处理，不能用已知 381 条详情和 756 条关系证明全源站完整。

### 4. 首批保持通用对账，样例解析单独隔离

实体、关系和分页的比较逻辑应只接收带来源定位、完整性标记和目标观测信息的标准快照。manwei 的保存证据适配和后续站点解析独立处理，不在通用检查器内写死分类名称、字段、记录数、选择器或 URL 格式。

AI 可辅助提出提取规则和映射，但程序验证其产物；后台关系、实际页面输出、源代码推导是不同证据层。无法提取或不完整分页应为 unverified，不得把空集合当作实际缺失，也不能将代码推导判为页面已实测。生成脚本提供的映射仍是待独立核验的线索。

## 实施顺序建议

1. 契约与纯对账，使用 manwei 保存证据及小型故障样本验证具体差异、证据不足和旧清单兼容。
2. 只读取证与来源放行，连同 ensureManifest 的长异常兜底修复；原异常留诊断证据，摘要受字段长度约束，规划失败不能放行正式全站迁移。
3. 接入同一优化链的结构化修复、版本与累计限制，再完成 message/临时文件交接及恢复。
4. 运行 manwei 原站原会话真实验收，检查关系、分页、双端及适用 SEO；在任务详情展示 checklist 及轮次证据，最后回到其他场景。

临时文件清理规则可在载体接入时按现有设计落实，不阻塞首批纯对账。平台特定的取证协议、提交机制和调度问题优先修代码；来源差异、内容映射等可复用判断方法再沉淀经验，避免把平台缺陷转成每次都需模型补救的 prompt。
