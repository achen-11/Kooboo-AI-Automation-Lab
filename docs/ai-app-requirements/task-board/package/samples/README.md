# 可复现样例

本目录全部是虚构测试资料，不含账号密码、令牌或发件配置。[scenario.json](scenario.json) 描述目标业务状态，供人工或生成后的初始化程序映射，不是 Kooboo 的导入格式，也不要求新增批量导入功能。

## 账号与角色

在隔离测试应用中，从已经获准使用的 Kooboo 测试账号映射这些符号；记录实际用户标识，不创建另一套账号体系，不把真实凭据写进本包。若尚无可用测试账号，记录该前置未满足，不伪造登录通过。

| 符号 | 展示名 | 项目 A：产品协作 | 项目 B：发布准备 |
| --- | --- | --- | --- |
| lin | 林 | 管理员 | 成员 |
| chen | 陈 | 成员 | 管理员 |
| jordan | Jordan | 成员 | 非成员 |
| sam | Sam | 管理员 | 非成员 |
| lee | Lee | 已离开，先加入再移除 | 非成员 |
| outsider | Alex | 非成员 | 非成员 |

项目名称在样例中唯一以便操作，不代表业务禁止同名。A、B 均为进行中项目，各有待办/进行中/已完成三列；待办为默认、已完成为完成列。

## 时钟与编号

- 固定参考时刻为 `2026-11-10T12:00:00Z`，只用于说明。执行初始化时读取真实服务端时刻为 T0，将 JSON 所有相对小时统一换算成实际时间点，不修改生产服务器时钟。
- 例如任务 `#0002` 的截止为 T0−2 小时；参考值为 `2026-11-10T10:00:00Z`，UTC+08:00 显示 18:00、UTC−05:00 显示 05:00。到期后同一时刻均逾期。
- 动作验收逐项重置场景并记录各次 T0，避免前项删除、归档或成员变化污染后项。到期前后边界场景使用即将到期的真实时间，或隔离测试进程的受控测试时钟，记录采用方式。
- 按 JSON 顺序创建，干净应用预期得到 `#0001`—`#0010`；已有任务时记录 taskKey→实际编号，不重置全局计数、不通过修改只读编号凑样例。不要求无间断编号。
- JSON 内创建、完成等相对时间描述目标历史；正常初始化通过业务动作建立并记录实际服务端时间。只有实施方已有隔离测试夹具时才可注入历史，必须说明方法，不能伪造生产操作日志。

## 建立顺序

1. 映射账号；林创建 A 并添加陈、Jordan、Sam、Lee，提升 Sam。陈创建 B 并添加林。核对两个项目的独立角色与初始列。
2. 按项目分别建立 JSON 标签及颜色，按 `creationOrder` 顺序跨项目创建任务，设置状态、负责人、优先级及相对 T0 的截止时间。
3. 将 `#0001`、`#0006` 实际切入完成列；将 `#0005` 归档。在 `#0006` 完成后移除 Lee，保留已完成任务负责人。不能直接把非成员作为新任务负责人。
4. 建立下述描述和评论，先真实上传图片取得受项目权限保护的服务器链接，再替换本地素材路径。图片被多处引用时记录实际资源身份。
5. 提及需使用成员选择器建立关联；普通 Markdown 的 @Jordan 文字不等于真实提及，按 JSON 中的 `mentionUserKeys` 选择真实用户。
6. 初始操作会自然产生日志及通知；记录基线未读数及邮件投递状态。后续通知验收按增量比较，不能把样例静态文字算为已发送通知。

## 通知增量场景

前置均为基线独立副本，各用户邮件开关打开且有授权测试邮箱；未满足邮件前置时单记待验证。

| 操作 | 站内及邮件有效接收人 | 不应收到 |
| --- | --- | --- |
| Jordan 将 #0002 从陈转交 Sam | 陈、Sam，各一次 | Jordan、林、非成员 |
| Jordan 将 #0002 从进行中改待办 | 林、陈，各一次 | Jordan、Sam、非成员 |
| 陈在 #0002 新增评论并真实提及 Jordan | 林、Jordan，各一次；陈因操作者排除 | 陈、Sam、非成员 |
| 陈编辑上述评论，保留 Jordan，仅新增 Sam 提及 | Sam 一次 | 林、陈、Jordan、非成员 |
| 林编辑 #0002 描述，新增两次陈提及 | 陈一次 | 林、Jordan、Sam、非成员 |

同次收件合并规则另用“Jordan 发评论并提及林、陈”验证：林及陈各只收到一次，而非评论通知加提及通知各一次。关闭陈邮件后只减少邮件，不减少陈的站内通知。不能发送到未获授权的真实收件人。
