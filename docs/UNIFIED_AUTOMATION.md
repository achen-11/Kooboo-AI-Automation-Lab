# Kooboo AI Automation Lab

本轮按 2026-11-07 确认的讨论方案实施。默认进入任务中心，界面沿用 CPR，图标使用 Lucide；侧栏支持收起 / 展开并记住状态，所有页面共用 Select 组件。

## 任务详情与信息层级

- 任务中心进入默认“概览”；报告列表进入“评测结果”。五个分区为概览、评测结果、执行记录、用量费用、输入与配置；具备能力的连接额外展示交付。支持 `#/tasks/:id?tab=report` 等直接链接，轮询不切换用户所选分区。
- 概览分别展示生成与评测执行状态、质量摘要、当前需要处理的事项、进展及费用摘要。完整 AI 原因、历史尝试与跟进计时放在执行记录。恢复按钮作用于需要恢复的原任务；“更多”中的生成跟进 / 重新评测创建新一轮任务。
- 用量明细和执行日志由服务端每页返回 20 条；用量支持阶段筛选。计费口径、原始 usage、完整上下文与版本标识通过 Lucide 展开控件查看。错误、待核算和未验证状态仍明确显示。
- 评分、问题及覆盖缺口放在结果分区。问题可展开其证据；全部截图默认关闭，每页 12 张，仅展开后加载图片。生成任务展示关联评测的结果，同时保留原生成 / 评测身份。
- 通知呈现任务名、事件与短摘要，点击进入任务分区。历史异常若已有后续进展会标注，完整诊断可从执行或交付记录查看。
- 新 UI 使用 `GET /api/automation/tasks/:id/summary`，`/usage?page=1&pageSize=20&stage=evaluation` 和 `/sections/{execution,input,report,delivery}`；execution 接受相同分页参数。任务列表与通知选择 `?view=compact`。原本完整详情、通知和外部报告 API 保留其数据契约。
- 可复用的 AI App 生成与评测观察点见 [信息层级审查参考](../sop/app-ui-information-hierarchy.md)，可纳入自定义 SOP / references；本次不改写已发布规则或历史评分。

本轮已通过平台类型检查、构建与接口回归；界面视觉及具体交互效果需由用户在 4180 验收，未以浏览器控制或截图模拟替代。

评测恢复保留原任务、站点、规则和经哈希校验的证据。Kooboo 生成会话与 Codex 评测会话独立保存，生成执行检查不会覆盖评测线程。明确的图片请求 / 上下文超限或本地 rollout 缺失会解除失效评测线程，供 AI 跟进选择在新会话中复用证据重试。图片评测 / 交付用量转发的请求体上限为 128 MiB，流程跟进为 32 MiB；超限保留明确错误，不无限增大请求。

评分输出先校验每条视觉指标的同视口 target PNG，以及存在参考站时的 reference PNG。校验失败把全部缺失指标 / 视口 / 角色反馈到原 Codex 会话，附最新证据清单，最多追加两次结果修正；失败记录和用量保留，持续失败再交流程跟进。宿主不自动改写分数或替 AI 配证据。评测恢复会直接传入跟进 Agent 查明的原因与要求，避免无反馈地重复整轮。

## 使用

1. 系统设置 → Kooboo 连接：复用或保存环境地址、访问令牌，保存后测试连接。
2. 系统设置 → 评测模型：同一卡片填写模型名称、API 地址和 API Key，统一保存，再测试图片识别与工具调用。默认模型 `deepseek-flash-1017`；API Key 留空保留已有加密密钥。首次显示实际生效的 API 基础地址，兼容已有 `/chat/completions` 或 `/responses` 地址。原评分执行器配置在后台兼容保留，不再作为第二张配置卡片展示。
3. 资源库：填写自由说明、需求、内容站 / 参考站和附件。无需 README 或固定文件格式。单文件上限 16 MB；外部来源与标识成对填写。
4. 在资源表勾选 checkbox 批量创建任务；创建窗口选择范围、环境、补充要求，并可预览委托消息。任务固定输入版本，网络重试使用同一请求标识。
5. 在系统设置启用自动执行。队列默认暂停；生成和评测分别受全局并发上限控制，生成页面由服务保持运行，管理页关闭不影响任务。
6. 生成结束后默认交接独立评测，可在设置关闭。自动评测沿用本次生成的输入版本、范围和同一生成站；缺少公开地址时记录原因，不虚构报告。
7. 资源详情保留多个生成站；可在既有站继续生成，选择全站范围用于首页样稿之后的续建，也可关联已有站点后评测。
8. 任务详情查看真实委托、状态、执行事件、AI 跟进动作及最近上下文。准备、生成、交接或评测异常时自动进入内置 AI 跟进；无法继续时交付中断说明。历史已停止任务可点击“AI 接管 / 恢复”，沿用原任务、生成站和证据。手动“提交跟进 / 重新评测”仍会创建新一轮任务。
9. 系统设置 → AI 跟进：调整启用开关、独立并发、次数、时间、token 预算及 SOP；跟进与评测复用现有模型配置。查看侧栏通知箱获取完成报告与中断结果，可按需启用浏览器桌面通知。

## 评测规则与证据

- SOP、参考资料、指标、权重、适用场景、范围、视口及必过项可编辑。保存并启用生成不可变版本，任务固定实际规则，新规则不改写历史。
- 草稿可保存在当前浏览器，未启用前不参与评分；这不是跨浏览器协同草稿服务。
- 默认 Site 视觉口径使用 Hero 40%、结构 40%、其他区段 20%。迁移 / 升级全站另有完整度、动态内容实现与 SEO 的可编辑初始规则；这些额外比例属于实施默认值。App 初始 UI / 业务比例同样可改。
- PC、移动端、业务分别给分，没有默认将它们合并为一个总分。平台根据适用指标的权重计算各组分值。
- 本地 Codex Agent 按 SOP 使用受任务约束的浏览器工具取证；管理平台不把页级图片诊断计数直接解释为视觉缺陷。
- 有分数的视觉指标必须引用本轮对应视口与角色的真实截图；平台校验证据清单、哈希、指标与范围。不存在的材料不能评分，未验证保留 `null`。
- 动态内容存储 / 路由、复杂业务与正式上线 SEO 缺少实现或实际结果证据时必须标记未验证。当前工具主要提供页面操作和截图，不因此宣称后端实现已经通过审核。
- 网站 UI / 业务操作仅在实际启用任务后执行。评测只审查和交付报告，不自动修复目标站；修复继续进入生成调度。

## 外部 Admin API

首版服务仍绑定本机。现有本地会话、导入与读取令牌沿用加密存储；不修改全局 Codex 配置或原运行数据。其他机器访问、任意外部网页跨域访问和生产认证需后续部署处理。外部服务可以通过 HTTP 接口对接，本机页面提供示例与令牌复制。

| 接口 | 授权 | 用途 |
| --- | --- | --- |
| `POST /api/v1/resources/import` | 导入令牌 | JSON 数组导入；相同外部来源 / 标识保存新的输入版本 |
| `GET /api/v1/automation/tasks?status=pending` | 读取令牌 | 外部 AI 查询任务状态和上下文 |
| `GET /api/v1/automation/reports` | 读取令牌 | 按 externalSource、externalId、resourceId 及分页读取多站多轮评测 |
| `GET /api/v1/automation/reports/:id` | 读取令牌 | 实际任务、固定输入、规则、报告及事件 |
| `GET /api/v1/automation/reports/:id/artifacts/:file` | 读取令牌 | 本轮真实证据，读取时重新校验哈希 |

无报告时 `report: null`，不返回假零分。读取令牌无任务创建、跟进或修改权限；当前跟进操作使用本地管理会话。文件附件先通过本地资源上传；外部 JSON 可使用已存在的附件标识，不能伪造文件元数据。历史评测接口继续可用。

## 中断与恢复

取消请求不立即释放执行名额；执行器完成清理之后才释放。正常失败自动进入内置 Codex 跟进；工具允许查任务、原会话、站点、首页可访问性及真实执行状态，再安排原任务重试、原会话继续 / 回答、交接评测、等待或中断。生成与评测使用独立会话。普通跟进不依据低分修改站点；显式启用的质量优化按以下流程执行。

### 自动优化到目标

AI Site 模板的新建生成任务可选择自动优化，默认 PC / 移动端各 85 分、最多修复 3 轮，不包含初次生成与初评。已完成且有有效当前报告的模板任务，可在“更多 → 自动优化到目标”显式启用，沿用原站、原会话、输入与规则。历史低分任务不会自行启动。

系统设置可修改默认目标、轮数、可选费用上限和质量分析 SOP；已启动任务使用冻结配置。跟进 AI 接收经哈希校验的双端目标 / 参考 PNG 及报告，整理修复委托后，Kooboo 在原站原会话修改。独立评测重新采集并复评，二者串行。Kooboo automation bridge 必须支持 `imageInput`，缺失时保留明确错误，不静默丢弃图片。

概览展示当前阶段与目标；评测结果默认展示当前版本报告，并按轮次查看历史报告、修复要求及改善分析；执行记录和用量支持按阶段 / 轮次查看。任务列表隐藏内部修复子任务，队列统计仍包含它们。首次质量分析初始化独立跟进预算，后续各轮累计，Kooboo 和评测等待不计入该活动时间。

双端均达到目标、适用必过项通过且无重大缺陷时达标停止。达到轮数上限、连续两轮没有实质改善、配置预算耗尽或 AI 提供明确无法继续的理由时停止并保留原因与下一步。不会自动回滚。费用上限覆盖历史建站、全部评测、跟进与修复，在阶段边界核算；已开始请求可能继续产生费用，费用不完整时不启动下一阶段。

`POST /api/automation/tasks/:id/optimize` 接收 `targetScore`、`maxRounds`、`maxCostCny`（可为 null），只允许本地管理会话开启已完成模板任务；`POST /api/automation/tasks/:id/optimization/stop` 停止当前流程。

外部 Admin 用读取令牌访问 `GET /api/v1/automation/tasks/:id/result`，获取当前版本结果、目标是否达到及报告引用。修复期间或改动后尚无有效复评时返回 `ready: false`、`report: null` 及原因；不能使用历史分数推测当前质量。流程停止但当前版本有有效报告时仍提供实际未达标结果。历史报告和证据 URL 保持可读。

真实验收：rendani 首页从初评 PC 76 / 移动端 78，经修复 1 的 78.8 / 84.8，自动继续至修复 2 的 91.8 / 91.0，并在双端达到 85 后停止。最终报告 `2dc18383-5b4d-4448-bb8f-537f08cf70a2` 的 190 份证据哈希通过，结果 API 与重启后的持久状态核验通过。仍有 1 项次要视觉差异及表单、其他断点等未验证项，报告原始 quality 为 unverified；这表示首页优化目标达成，同时保留审查局限，不代表全站 / 业务验收。完整过程见讨论记录末尾。

跟进 token 上限目前是 Agent 会话边界限制，单次会话内的多次请求可能超量；本次两次质量分析累计约 422 万 token，超过配置的 200 万。费用阶段边界限制同样不等于严格实时硬封顶。完整 usage 保留，调用协议补全后的降耗效果尚待后续案例验证。

重试保留输入 / 规则快照与已验证证据，生成完成后刷新地址并幂等交接评测。创建或发送结果不确定时不重放；旧任务先核对原会话。若无法确认原执行已停止，继续占用名额并明确中断；检查原会话 / 进程后，在任务详情确认停止，再恢复。一个数据目录只允许一个新自动化 worker。

AI 跟进默认并发 1、5 次、20 分钟、150000 token，可在设置修改。接管后固定策略；显式恢复采用当前策略并重置预算。时间仅累计跟进 Agent 的实际活跃执行，排队、定时等待、Kooboo 生成和独立评测不计入；每秒保存检查点，重启不加入停机时间，单次 Agent 最多 5 分钟。token 按请求 / SDK 已知用量在轮次间校验，不能严格截断当前请求。

任务中断说明包含原因、证据、尝试记录、下一步和恢复位置。报告完成 / 中断进入持久通知箱，页面打开时浮动提示；桌面通知须用户启用且页面保持打开。关闭管理页后后台继续执行，首版尚无页面关闭后的系统推送。

### AI 跟进工具连通性
