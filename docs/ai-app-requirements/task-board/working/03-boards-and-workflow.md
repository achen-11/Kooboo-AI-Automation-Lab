状态：结构、颜色、列删除保护、移动、排序、默认列、完成列、完成时间与状态日志已确认；部分跨模块边界待后续补齐。本文件保留过程，不作为生成资料上传；正式需求见 [看板、状态与任务移动](../package/03-boards-and-workflow.md)。

## 已确认的前提

- 系统支持多个项目，每个项目有独立看板和成员。
- 项目内有管理员、成员两种身份，项目与任务仅成员可见。
- 项目归档后看板与任务只读，恢复后重新允许正常操作。
- 真删除项目时一并删除该项目的看板和任务。

| 主题 | 已确认规则 |
| --- | --- |
| 看板数量 | 每个项目一个看板，创建项目时自动建立 |
| 初始列 | 默认提供待办、进行中、已完成三列 |
| 列与状态 | 看板列直接表示任务状态，任务移动到目标列即更新其状态 |
| 列管理 | 项目管理员可以新增、重命名、排序和删除列；普通成员不能修改列结构 |
| 列颜色 | 每列提供颜色字段，用于区分列和任务状态；颜色随列配置由管理员维护 |

本轮明确选择每项目一个看板，已同步正式需求。颜色是用户补充的业务展示要求，具体色值不作为完成状态判断依据。

## 已确认的第二组规则：列删除、任务移动与日志

用户回复“符合预期, 不过状态的改变要有日志记录, 谁在什么时间修改了哪条任务”，认可本组四条建议并补充状态变更日志，见 D026—D030。

| 主题 | 已确认规则 |
| --- | --- |
| 列删除 | 管理员只能删除空列；有任务时需先将任务移到其他列，删除列不删除任务 |
| 移动权限 | 项目管理员与普通成员均可移动本项目内的任意任务 |
| 移动方式 | 支持拖拽，也可在任务详情中切换状态 |
| 流转限制 | 允许跳转、回退及从已完成返回其他状态，不强制逐列流转 |
| 状态日志 | 每次实际状态变更记录谁、何时、哪条任务及前后状态；拖拽与详情切换均记录 |

上述行为均受项目归档后只读的已确认规则约束。本组不提前决定跨项目移动。

## 已确认的第三组规则：默认列、完成列与排序

用户回复“符合预期”，确认上一轮四条建议，见 D031—D034；已同步正式需求。

| 主题 | 已确认规则 |
| --- | --- |
| 默认列 | 管理员指定一个默认列，初始为待办；创建任务未指定状态时进入默认列 |
| 完成列 | 管理员指定一个完成列，初始为已完成；任务位于该列时视为已完成，列重命名或排序不改变其完成含义 |
| 列保护 | 默认列与完成列必须不同，至少保留两列；删除这两类列前需先重新指定替代列，并遵守只能删除空列 |
| 任务排序 | 同列支持手动拖拽排序；跨列移动默认放到目标列末尾 |

日志中如何保留列名变更前的历史表述，在操作记录模块细化；仅调整同列顺序不会产生状态变化，是否记录排序行为也在该模块决定。

## 已确认的第四组规则：完成时间与完成列调整

用户回复“符合预期”，确认上一轮三条建议，见 D035—D037；已同步正式需求。

| 主题 | 已确认规则 |
| --- | --- |
| 完成时间 | 任务进入完成列时记录本次完成时间；创建时直接选择完成列，也记录完成时间 |
| 重新打开 | 任务离开完成列后清空当前完成时间，原完成及重新打开记录保留在日志中；再次完成记录新的完成时间 |
| 更换完成列 | 首版仅在原完成列与新完成列均为空时允许更换，避免仅改列配置就批量改变已有任务的完成含义 |

该组选择用空列约束避免配置变化直接改变已有任务的完成含义。原完成列或新完成列有任务时，需先按正常移动规则处理任务，状态变化仍须留日志，并按完成或重新打开规则更新时间。
