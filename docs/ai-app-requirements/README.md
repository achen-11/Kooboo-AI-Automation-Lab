# AI App 需求资料包整理

本目录记录从业务讨论到生成资料包的过程。先在本地整理完善需求与资料，再导入 Automation Lab，由 Kooboo AI 根据资料生成，独立评测依据同一份冻结资料验收。

## 整理方法

1. 先明确系统目标、组织范围、角色与数据可见范围，再讨论各业务模块。
2. 每轮集中处理一个模块，给出完整推荐行为及真正影响业务的取舍；允许整组确认或仅指出修改项，避免反复细问实现细节。
3. 在案例的决策记录中保留问题、候选方案、最终选择、依据与影响。用户未逐项决定但可合理补齐的细节单列为“整理默认”，给出来源，供整体复核；不能伪装成用户原话。
4. 确认的内容同步写入 `package/`；讨论中的内容留在 `working/`。模块存在未决问题时明确标明，不能把局部确认写成模块已定稿。
5. 需求用业务语言表达，包括正常流程、异常分支、权限、数据规则和可观察结果；不要求用户先设计数据库、API 或 Kooboo 内部规划对象。
6. 跨模块检查术语、状态、权限和数据关系。需求中的预期结果必须能追溯到用户要求或已确认的决策，不能从生成结果反推验收标准。
7. 将跨模块规则展开为统一权限矩阵，再建立有具体身份、动作、时间、内容及数量预期的样例；逐项验收写明前置、操作、预期及结果证据。检查入口、链接、样例和哈希，形成复核版本；固定所用版本后再生成与评测。
8. 真实执行后记录资料歧义、遗漏、人工介入和实际结果，据此修订整理方法；一次生成成功不直接视为方法已普遍有效。

## 文件职责

- 案例 `README.md`：模块进度、阅读入口与当前问题。
- `decisions.md`：决策过程及变更理由；旧结论被替代时保留记录。
- `working/`：候选方案、待讨论问题和未定稿草案，不作为上传资料。
- `package/`：正式业务需求、单独列出的整理默认、样例、图片及未执行的验收模板。整体复核后冻结生成输入。
- 案例 `build-package.py`：检查引用、样例及验收编号，输出 manifest 和仅含 package 的可重建 ZIP。
- 案例 `review-and-run-log.md`：资料版本、复核、真实生成、实际验收与改进记录，未执行不预填成功。

决策和需求在当前仓库随文件版本保留。生成测试、评测结果和方法改进需有实际证据后再补记，不提前填写通过结论。
