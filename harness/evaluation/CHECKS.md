# 独立评测反模式红线清单（CHECKS.md · 一错一规种子库）

本文件是自动化平台「**一错一规（One Rule Per Mistake）**」机制的基线红线规范，记录已经从历史实测与人工复核中沉淀的核心视觉、布局、内容与覆盖率红线。

- **运行时动态扩展与版本冻结**：本机运行时新增或修订的人工复核规则、豁免条目及标定反例持久化在本地 SQLite 数据库（`auto_checker_checks` / `auto_checker_check_revisions` / `auto_checker_calibrations`），**不会反向改写本源码文件**。每次启动独立评测时，宿主按任务的 `scenario × scope` 提取当前启用的规则快照，写入该次评测工作目录 `CHECKS.md`，并随报告持久化 `checksSnapshot`（含哈希与规则列表）。
- **宿主机硬封顶（不依赖模型手软）**：命中 `Critical` 或 `Major` 红线时，宿主裁决引擎（`applyBoundedVerdictCaps`）会自动把对应维度与视口总分封顶，并强制判定 `quality = "failed"`（且 `humanSummary.verdict !== "ready"`）。

---

## 首批反模式种子规则

### `R-VISUAL-01` [MAJOR] 非豁免场景下禁止用大块 SVG 充当主视觉或展示卡片
- **触发条件**：Hero 主视觉或精选作品/产品/服务展示卡片中缺少真实高质量图片（或 Kooboo 推荐的 `imagePlaceholder` 真实配图 `<img>`），而用大面积纯几何线条/渐变/光锥等 `<svg>` 或纯 CSS 图形充当视觉主体。
- **明确豁免**：
  - 工具型 SaaS 界面示意
  - 技术架构图 / 流程图
  - 数据可视化图表
  - 品牌 Logo 与小尺寸 UI 功能图标
- **宿主封顶与动作**：对应维度封顶 `≤ 70`，对应视口封顶 `≤ 75`；判定 **Major**，强制 `quality = failed` 且 `verdict ≠ ready`。

### `R-VISUAL-02` [MINOR] 配图语义、语种与品牌语境一致
- **触发条件**：页面配图出现与站点语种/品牌违和的外语价签/招牌文字、无关第三方设备或竞品 Logo 抢镜，或配图与所属业务卡片语义明显不符。
- **明确豁免**：
  - 明确作为展示对象的真实商品原包装/跨国品牌原物
- **宿主封顶与动作**：局部卡片配图记 **Minor** 并要求替换；若出现在 Hero 或核心卖点主图则升格为 **Major**（对应维度 `≤ 72`、视口 `≤ 78`）。

### `R-LAYOUT-03` [MAJOR] 移动端首屏对齐与防截断硬线
- **触发条件**：出现横向溢出（`scrollWidth > clientWidth`）、固定 Header 遮挡 H1/首屏内容、移动端主体/CTA 严重错位、页脚/卡片内容被截断，或移动端导航菜单展开后缺少可见可点击的关闭入口／遮罩拦截关闭按钮。
- **明确豁免**：无。
- **宿主封顶与动作**：对应维度封顶 `≤ 72`，对应视口封顶 `≤ 75`；判定 **Major**，禁止被基础结构通过项稀释为高分。

### `R-COVER-04` [MAJOR] 必检项未验证比例过高禁出满分或高分放行
- **触发条件**：必检项目或关键页面范围存在缺失证据导致未验证，禁止仅因局部已验项全部通过而给出 90–100 分或直接 `passed`。
- **明确豁免**：无。
- **宿主封顶与动作**：维度不硬封顶（`null`），对应视口封顶 `≤ 78`；分离质量得分与覆盖率，存在未验必检项时保留 `unverified` 或降档拦截。

---

### `R-LAYOUT-04` [MAJOR] 首屏安全线越界或分栏图文高度失衡
- **触发条件**：首屏主 CTA/内容主图越出视口安全线（`H1` 贴近导航底或核心内容被裁半），或桌面双栏图文高度差超过容差 `max(48px, 短列 8%)`（含直接沿用参考站失衡分栏，未按 `relative + absolute` 或纵排多图重构）。
- **明确豁免**：媒体列使用 `position: sticky` 或 ≥3 列等宽纯卡片网格，不按双栏图文失衡判定。
- **宿主封顶与动作**：对应维度封顶 `≤ 75`，对应视口封顶 `≤ 78`；标记 `Major` 并要求修正首屏安全线与双栏等高/多图纵排布局。

---

### `R-TYPO-01` [MAJOR] 全局最小字号违规或语种本地化失真
- **触发条件**：页面存在 ≥10 处可见文字小于 `12px`（如沿用参考站 `10–11px` 小字/标签），或 `<html lang>` 与目标站点主语种不符、非中文站残留中文字符、原生 `<input type="date">` 隐式出现 `年/月/日`。
- **明确豁免**：品牌 Logo SVG 内嵌装饰文字或 `aria-hidden="true"` 副本除外。
- **宿主封顶与动作**：对应维度封顶 `≤ 75`，对应视口封顶 `≤ 78`；标记 `Major` 并要求将可见文字统一抬升至 `≥ 12px`、对齐 `<html lang>` 并替换原生日期输入控件。

---

### `R-DUPE-01` [MINOR] 同页联系方式、CTA 文案或正文段落重复超限
- **触发条件**：违背 H32「一次完整 + 一次精简」原则，同页电话/邮箱整页 > 3（正文 > 1）、相同 CTA 文案整页 > 3（正文 > 2，未按区块替换场景词）、正文/标题完全重复或内容图复用 > 2 次。
- **明确豁免**：带 `aria-hidden="true"` 的轮播/跑马灯无缝循环副本除外。
- **宿主封顶与动作**：对应维度封顶 `≤ 82`，对应视口封顶 `≤ 85`；标记 `Minor` 并要求去重冗余副本、按区块区分 CTA 文案。

## 人工复核「一错一规」沉淀工作流

1. **发现漏判或虚高**：审核员在评测报告页（`TaskReport` -> `问题清单`）发现漏判/虚高问题，点击「沉淀为 CHECKS 规则」或问题卡片上的「沉淀为 CHECKS 规则」。
2. **结构化入库**：填写或自动带入规则编号（如 `R-CONTENT-01`）、严重度、触发条件、适用场景/范围、封顶阈值，并勾选「同时沉淀为自动回归标定反例」绑定当前真实截图证据。
3. **发现误判纠偏（追加豁免）**：审核员切换为「追加规则豁免」，在目标规则下补充豁免条款并生成 `should-pass` 标定反例，防止同类合理页面被误伤。
4. **零 Token 确定性回归 & 真图复验**：在「评测规则 -> 红线规则（CHECKS.md）」或运行 `node --import tsx scripts/checks-regression.ts --deterministic` 验证每条标定反例在 Prompt 注入与宿主封顶层严格通过；必要时可用 `--live --case <id>` 以真实 PNG 调模型复验。
