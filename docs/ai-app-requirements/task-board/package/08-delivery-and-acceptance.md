# 真实数据、交付与验收

状态：原则、具体样例与验收清单均已整理，纳入 v1.0-review 整体复核；当前尚未生成、部署或实际验收。

## 持久化

- 使用 Kooboo 的真实服务端存储保存项目、成员关系、任务、评论、图片、日志、站内通知及个人偏好。
- 刷新页面、退出重新登录或服务重启后仍可读取已成功保存的数据，权限不变。
- 不以 mock、仅内存或浏览器本地数据冒充服务端持久化完成。
- 账号身份复用 Kooboo，项目身份由应用维护，邮件配置不写死在源码。

## 交付内容

- 完整源码、环境与发件服务配置说明、初始化步骤，以及数据与图片的备份恢复说明。
- 明确邮件未配置、账号无邮箱及发送失败时的处理和诊断方式，真实邮件交付须验证收件。
- 具体数据库、图片存储与邮件实现由生成阶段结合 Kooboo 选择，并留下实际配置及验证结果。

## 样例资料

- 准备至少两个项目、多名具有不同项目角色的用户。
- 覆盖未完成、已完成、逾期、归档、不同优先级、标签、分配与未分配、正文图片及 @提及。
- 样例明确标为测试数据，与真实业务数据区分，不在交付中混入真实凭据。
- 具体身份映射、初始化步骤、任务数据、Markdown 及图片见 [样例说明](samples/README.md)；样例 JSON 是场景数据，不声明现成导入接口。

## 验收要求

- 提供功能、访问权限、并发、服务端持久化、图片、通知及真实邮件收件的可执行验收清单。
- 记录每项实际结果和证据，未执行或未验证不能记为通过。
- 采用与生成相同版本的需求资料进行独立评测，区分生成完成、静态验证、运行验证与最终验收。
- 时间采用 [精确截止时间与跨时区显示](09-time-and-timezones.md) 的已确认方案；验收覆盖跨时区显示、同一时间点逾期一致、同日到期前后、夏令时输入、日期筛选及换时区不改写数据，不能使用固定北京时间替代。
- 逐项前置、操作及预期见 [可执行验收清单](12-acceptance.md)，结果填写 [CSV 模板](acceptance-results.csv)；全部初始为“未执行”，不能以模板存在代替实际证据。

对应决策：D120、D121；账号、邮件及完整交付沿用相关已确认规则。
