# 迁移检查接入修复与回归

2026-11-08。在[首批检查器](migration-checklist-phase1.md)基础上，将宿主程序对账接入正式报告及原优化链。首个支持的宿主适配器为 `manwei-v1`，需要明确登记实体目录、关系目录及冻结来源任务；其他网站不自动套用这些字段或选择器。

## 本批行为

1. 登记时只读原工作流的已保存来源证据，校验文件大小及 SHA-256，再由宿主适配器建立结构化基线。继承当前独立报告的全部必交付要求，保存新清单版本；历史报告和原预算保持不变。来源未知范围仍然未知，不根据目标站缩减来源。
2. 已登记工作流每次独立评测结束后，由宿主顺序读取选定后台目录的全部分页，并请求冻结路径全集。每次最多300次只读请求、180秒，不调用模型。目录不完整、路径失败或未知版式如实保留；不跟随重定向，也不以源码推导代替响应。
3. 检查运行记录输入、实际站点ID、平台修订、清单版本、基线哈希、检查器版本和原始证据引用。`migration-v2` 增加 `expectedKeys` / `checkedKeys`，明确每次实际核对了哪些路径和标识，避免以较小分页基数覆盖原范围。当前`migration-v3`新增manwei案例`case-list`的输出提取；旧运行保留，跨版本不自动计算已解决差异。
4. 新报告保存 `migrationCheck`。确认失败使完整性和质量失败；未验证项阻止迁移整体通过。程序结果不改写数值评分，也不能替代正文、视觉、交互及其他清单要求的独立验证。
5. 优化分析的 `get_report` 提供程序具体差异、独立报告全部问题及未通过清单项。宿主在实际创建修复子任务时再次完整附入消息；即使规划AI漏写问题，必修差异仍保留。继续使用原站、原Kooboo会话、固定输入与规则、原累计预算；图片仍按现有机制校验和交付。
6. 修复后的独立评测会重新检查同一冻结范围。跨轮比较采用宿主 `compareMigrationRuns`；证据退化、清单不可比或仍有未验证局限时，不把差异消失当作已解决。视觉改善分析仍由原独立图片流程提供，程序比较单独记录在修复上下文中。

第41图的资料交付分支已补入实际生成器：平台先在 `auto_generation_context` 保存绑定任务、输入版本、站点、修订和清单版本的完整原件；最终文本超过24 KiB时采用短消息加临时kfile索引。这个数值是根据本案例约808KB文本事故设定的保守传输上限，不代表模型上下文容量。实际图片仍独立交付，并检查20张、24 MiB及整个JSON委托的总量；过限直接中断，不原样自动重试。

大包拆为每个不超过8 KiB的JSON节点；对象按字段引用、数组按连续区间、长文本按顺序分片，重复节点按哈希复用。索引解释还原规则，要求脚本内读取和批量处理，只返回计数、差异及必要摘要；禁止递归全文返回聊天。平台保留完整原文，不截断或缩减来源范围。文件只使用登记过的任务/包专属精确路径；写入后在Kooboo脚本内全文回读比较，只回传确认数。

首次真实执行发现，单靠格式说明仍可能让模型把数组节点错误拼成字符串。格式v2因此随包提供实际可执行的`reader.js`，短消息给出`k.file.read`和`automationRead("manifest")`的完整调用示例；指令、经验、清单可分别在KScript内还原。格式版本进入包哈希，升级不会覆盖仍在执行的旧包。还原脚本的测试直接执行随包发出的代码，核对完整数组、长文本和Unicode，而不另写一份测试专用解码器。此项不能代替真实环境的读取确认。

中断保留文件，恢复按同一原件与版本幂等投放；成功终态与会话证据保存、浏览器关闭后清理。本轮明确取消且执行停止也可清理。删除前逐文件确认内容一致，删除后确认不存在；修改或未知归属文件保留。清理失败单列 `pending-cleanup`，不改变内容评测结果，可通过下列接口重试。临时文件不得成为业务运行依赖。独立模型是否遵守按需读取仍须真实执行核验，程序不会声称仅凭分片就能保证整段会话不再增长。

本适配器要求每轮结构化基线与登记时的宿主提取一致。独立评测可以追加通用清单要求；若修改结构化来源标识、路径或覆盖事实，则停止并要求宿主重新解析来源，不接受AI仅凭有效证据文件名编造新的来源记录。结构化来源扩展工作流尚未接入。

## 恢复与互斥

在程序取证前，将已校验的AI报告及其输入、清单、修订和规则绑定保存为 `migrationPendingReport`。程序阶段中断后恢复原任务时，先复核报告证据哈希，再复用原评分完成程序检查，不重新请求评分模型。绑定或证据变化时拒绝沿用。该恢复仍遵循原任务的累计次数、费用和token限制，不绕过宿主预算准入。

手动程序检查只作用于当前已停止的站点，持有最多240秒的站点读取预约；期间不领取同站生成或跟进执行，服务异常退出后预约可过期。每次检查保存独立的原始响应和目录分页。尚未发布的程序取证遇到中断时会重新取证；本批复用的是已验证的AI评分阶段，不声称已实现程序每条HTTP请求的断点续传。

## 本机接口

沿用现有本机会话和来源限制，不提供模型提交已计算结果的入口。

| 方法与路径 | 行为 |
| --- | --- |
| `POST /api/automation/tasks/:id/migration/profile` | 登记 `sourceTaskId`、`expectedManifestId`、`contentFolderId`、`relationFolderId`；同工作流只登记一次 |
| `GET /api/automation/tasks/:id/migration` | 返回登记信息、当前有效检查及历史检查 |
| `POST /api/automation/tasks/:id/migration/check` | 当前站点的手动只读检查；不创建生成任务，不恢复优化，不重置预算 |
| `GET /api/automation/tasks/:id/migration/repair-context` | 返回实际附入修复消息的完整结构化上下文；不启动修复 |
| `GET /api/automation/tasks/:id/migration/:runId/evidence/:name` | 在所属工作流内，核对大小与哈希后读取目标取证原件 |
| `GET /api/automation/tasks/:id/generation-context` | 查询资料包版本、大小、路径及清理状态，不返回完整正文 |
| `POST /api/automation/tasks/:id/generation-context/cleanup` | 完成或取消、已停止且同站无活动执行时，仅重试登记文件的清理 |

运行结果及目标原件位于本机 `.data/migration-runs/<runId>/`。登记和检查分别存入SQLite的 `auto_migration_profiles`、`auto_migration_checks`；保留现有 `.data` 和主密钥，不复制到Git。

## 原案例实际验证

原任务 `f23d9437-c9b0-4329-b851-796e6aa1d7aa` 已登记，继承第2轮独立报告清单并保存版本3。使用原初评保存的来源固定153条分类及分页路径，没有用后来报告的较小分页数替换它。

真实只读运行 `810f217c-9fa6-4b06-9437-f85c8502a248` 保存166份目标证据：13页后台目录与153份路径响应。

| 检查 | 来源 / 实际 | 结论 |
| --- | --- | --- |
| 实体 | 483 / 483 | 已知键无差异；来源及未知版式局限仍使其为unverified |
| 后台关系 | 756 / 752 | 确认缺184→1045、1047、1046、1048 |
| 页面输出关系 | 756 / 752 | 部分内容提取不完整，缺失保持未确认 |
| 冻结路径 | 153 / 153 | 确认`/cn/category/184_4.aspx`响应404；保存全部checkedKeys |

修复上下文含5项程序确认差异和正式报告的6个问题，正文、内链等报告问题一并保留；实际上下文约37KB，未触及消息上限。通过本机接口验证历史报告不变、跟进配置及累计计数不变。优化仍为stopped、累计跟进5/5，轮次记录仍为初评加两轮修复，没有启动第3轮。

本批验证了真实读取、宿主对账、结果保存和修复上下文生成。实际新修复消息投递、修站和新一轮复评没有运行；它们受现有预算停止边界约束。正文、错误内链、模板与移动端缺陷尚未修复，来源覆盖、真实业务和生产部署仍有局限。
