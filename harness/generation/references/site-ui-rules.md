# 企业官网生成 UI 与版式硬约束（v1.2）

本规范将 UI 团队沉淀的《AI 生成企业官网规范（v1.2，版式平衡 + 内容去重版）》适配融入平台 `generation` 阶段，适用于 `materials`（资料建站）、`upgrade`（旧站升级）、`migration`（站点迁移）与 `site-template`（AI Site 模板）等公开站点场景。

> **冲突裁决优先级**：可读性 > 信息结构 > 版式平衡 > 一致性 > 视觉还原 > 动效。  
> **平台边界**：旧站升级与资料建站的事实保真优先于排版美化；禁止为了凑满版式或消除留白而编造数据、价格、证言或品牌信息。

---

## 1. 单首页与残留清理（H01 / H22）

- 一个生产站点只能有**唯一首页 `/`**；删除模板自带的 `Home 2 / Home 3`、`Demos`、`All Pages` 演示菜单与冗余示例页。
- 严禁残留 `Lorem ipsum`、`Edit me`、`Your text here`、`Company Name Here` 或原模板品牌名称。
- 按任务 `scope` 控制页面边界：`homepage` 任务只交付首页，不擅自扩展内页；`site` 任务补齐所需内页并保持内页 `<h1>` 底部 ≤ 视口 70%。

## 2. 首屏三条安全线与 C 位居中（H02 / H26 / H28）

- **完整可见（1440×900 / 1280×800 / 390×844）**：`eyebrow + H1 + 副文 + 主 CTA + 首屏主图` 在首屏内完整呈现，任何按钮或主图不得被视口底部裁半。
  - CTA 底部 ≤ 视口 − 40px（1440×900 ≤ 860px；1280×800 ≤ 760px）；主图底部 ≤ 视口高度。
  - 首屏文本块（eyebrow → CTA）高 ≤ 640px（900 高）/ 560px（800 高）；`H1` 顶部 ≥ 导航底部 + 32px。
- **屏幕中心聚焦**：首屏文本块垂直中心落在视口 **44–56%**（目标 50%），使用 `display: grid; align-content: center`；禁止 `justify-content: flex-end`、超大 `padding-top` 或 `min-height: 100vh` 底部对齐。
- 超出预算时依次微调：精炼副文冗余句 → 精简次要 bullet → H1 字号减 8%（≥ 40px）→ 合并次 CTA，不得丢失核心业务事实。

## 3. 标题行数与干净断行（H05 / H27）

- 首屏 `<h1>` ≤ 3 行（优先 2 行）；`<h2> / <h3>`、区段标题与卡片标题 ≤ 2 行；eyebrow / 标签 1 行。
- 4 行即不合格，通过缩字号（≥ 40px）、适度放宽容器或精简修饰词修正，**禁止用 `-webkit-line-clamp` 截断标题**。
- 使用 `text-wrap: balance` 与合理 `max-width`，末行不得只剩 1 个英文单词或 1 个汉字（必要时用 `&nbsp;` 绑定末尾词）。

## 4. 分栏图文等高与纵排多图（H25 / H31）

- 双栏图文（左文右图 / 左图右文）视觉高度差必须 **≤ `max(48px, 短列 8%)`**；即使所参考的外部站点/旧模板本身存在分栏高度失衡或大块留白，生成时也必须按本条重构，不得沿用参考站失衡结构。
- 媒体列必须脱离图片固有宽高比撑高，使用「`relative` 外壳 + `absolute` 内层 + `object-fit: cover`」，不能仅写 `height: 100%`：
  ```css
  .split { display: grid; grid-template-columns: minmax(0, 1fr) minmax(0, 1fr); align-items: stretch; }
  .split__text { align-self: center; }
  .split__media { position: relative; min-height: 100%; overflow: hidden; }
  .split__media img { position: absolute; inset: 0; width: 100%; height: 100%; object-fit: cover; }
  ```
- **文字列过高时纵向多图补全**（4:3 单图高按 `0.75 × 列宽` 估算）：
  - `textH ÷ 单图高 > 1.4` → 拆 **2 张纵排**；
  - `> 2.2` → 拆 **3 张纵排**（每张 ≥ 180px、`gap: 16–24px`，总高与文字列对齐）；
  - `> 2.8` 或超过 2 屏 → 使用 `sticky` 媒体列（H25 唯一例外）或拆分为两个 section。禁止一张小图配超长文字。

## 5. 文字与图片双可见（H16 / H29）

- 正文/按钮对比度 ≥ 4.5:1，大字（≥ 24px 或 ≥ 18.66px bold）≥ 3:1；品牌色作文字色必须达标。
- 图上压字必须使用**方向性渐变遮罩**（文字侧 55–70%、主体侧 ≤ 20%，全屏图文占宽 ≤ 52%），严禁全图 >70% 压黑导致图片主体不可辨。
- 图片可见且 `opacity ≥ 0.6`，保持 `object-fit: cover` 与合理 `object-position`，不得拉伸变形。

## 6. 反空旷与事实保真边界（H30）

- 单屏空白 ≤ 40%，分栏短列内容高 ≥ 长列 75%，非首屏 section 内容占比 ≥ 50%，连续空白 ≤ 240px。
- 修复顺序：**从既有资料/旧站提炼真实事实 → 补真实或合规 `imagePlaceholder` 配图 → 改单栏/调整版式 → 降低 `min-height` 与 `padding`**；禁止用空 `div` 或纯渐变填空白，**严禁捏造统计数字、资质或虚假客户证言**。

## 7. 排版、组件、本地化与动效卫生（H03–H19 / H21 / H23）

- **字号底线**：全站所有可见文字 ≥ 12px（**强制覆写参考站 10–11px 小字、角标与标签**；正文 ≥ 14px 推荐 16px、按钮 ≥ 14px、页脚 ≥ 13px、版权 12px）。
- **导航与响应**：≥ 1024px 桌面端导航吸顶（高 64–80px，左右内边距与容器对齐），禁止出现汉堡菜单；全站无横向溢出（`scrollWidth <= innerWidth + 1`）。
- **卡片与价格表**：卡片等高、内容顶对齐、CTA `margin-top: auto` 贴底；网格不留空洞（3/6/9、4→4列或2×2、5→3+2居中或2列），数据为空时隐藏 section 或显示空态；价格表桌面横向 3 列等高，禁止纵向堆叠。
- **按钮与表单**：按钮全站 ≤ 3 类（Primary / Secondary / Text），每屏主 CTA ≤ 1；表单有标题与说明、label 在上、输入框 44–48px、图标距边 12–16px。
- **页脚与暗色**：页脚使用 3–4 列文本链接而非按钮墙；暗色页面必须设 `color-scheme: dark` 与暗色细滚动条。
- **间距与动效**：8pt 间距 token，section 垂直间距全站统一一档（96/120/160）；动效仅动 `transform/opacity`（≤ 800ms、位移 ≤ 24px），支持 `prefers-reduced-motion` 且无 JS 时内容默认可见。
- **语种本地化**：`<html lang>` 严格匹配目标站主语种；非中文站禁止残留中文字符，且禁止使用浏览器原生 `<input type="date">`（须改用文本输入或自定义日期选择，避免隐式显示 `年/月/日`）。

## 8. 同页重复信息受控（H32）

- **计数口径**：按同一号码/邮箱/地址分别统计；轮播或跑马灯无缝循环副本须加 `aria-hidden="true"`。
- **放置原则（「一次完整 + 一次精简」）**：
  - 电话 / 邮箱：整页 ≤ 3（正文 `main` ≤ 1）；
  - 地址 / 营业时间：整页 ≤ 2（正文 `main` ≤ 1）；
  - 相同 CTA 文案：整页 ≤ 3（正文 `main` ≤ 2，不同区块按场景换词，禁止全页复读同一按钮文案）；
  - 相同段落 / 标题：0 重复；同一内容图片：整页 ≤ 2；
  - Header 已有电话时 Hero CTA 不再重复号码文字；Contact section 已有完整地址与联系块时，Footer 仅保留精简联系行 1 次。

## 9. 平台模式衔接说明

- **`direct-template` 原位改造**：保留 Kooboo 模板原生 `Page / Layout / View / kooboo-var.css` 视觉 DNA 与骨架，原位应用上述首屏、图文等高、去重与组件约束，不推倒重写，并一次完成代码落地。
- **其他模式（外部参考 / `reference-sandbox` / `materials`）**：保留参考视觉 DNA（字体气质、色板、圆角、图像风格与签名元素），先在内部规划好每个 section 的文/图高度关系与联系信息落点，直接一次完成代码落地（不要停留在分析阶段不写代码）。
- **验收分工**：浏览器三档截图与 DOM 体检由平台 Playwright 预检与评测端承担，生成端无需调用受限浏览器操作。
