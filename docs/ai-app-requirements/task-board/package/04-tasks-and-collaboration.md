# 任务创建、详情、分配与协作

状态：任务、评论、图片及字段规则已整理，独立附件已取消；编号等补充默认单列供整体复核。

## 任务基本字段

| 字段 | 已确认规则 |
| --- | --- |
| 任务编号 | 系统生成，如 #0001；不可修改，编辑、归档恢复不变，删除不复用 |
| 标题 | 必填，用于表达任务内容 |
| 描述 | 选填，用于说明任务内容与要求，支持 Markdown 格式 |
| 负责人 | 最多一名，也可暂不分配；只能选择当前项目成员 |
| 优先级 | 低、普通、高、紧急四档，默认普通 |
| 截止时间 | 选填，填写日期与具体时间，明确录入时区；转换为 UTC 保存，按用户时区显示 |

任务状态、默认列、完成列及完成时间沿用 [看板模块](03-boards-and-workflow.md) 的已确认规则。

## 截止时间与逾期

- 截止时间表示全球唯一到期时刻，录入时明确时区，统一 UTC 保存，按用户时区显示，详见 [精确截止时间与跨时区显示](09-time-and-timezones.md)。
- 服务端比较当前时间与截止时间，有截止时间且未完成的任务超过截止时刻后显示逾期，同一时刻对所有成员结果一致。
- 无截止时间或已完成任务不显示逾期；重新打开后按原截止时间与当前时间重新判断。
- 个人时区改变不修改任务到期时刻，不要求项目业务时区，不再采用截止次日起才逾期的旧规则。

## 任务组织边界

- 使用独立任务，不提供子任务或父子任务层级。
- 任务固定属于创建时的项目，不支持跨项目移动；任务状态切换仅发生在本项目看板内。

## 任务创建、编辑与分配权限

- 项目管理员和普通成员均可在本项目创建任务。
- 新任务排在所选状态列末尾；未指定状态时进入默认列末尾。
- 项目管理员和普通成员均可编辑本项目任意任务的标题、描述、优先级、截止时间及标签，不限定为创建人或负责人。
- 项目管理员和普通成员均可指定、更换或清空本项目任意任务的负责人，只能选择当前项目成员。
- 上述操作遵守项目成员访问范围；项目或任务归档后，任务只读。
- 编辑任务字段的权限不扩大项目标签重命名、删除权限或他人评论正文编辑权限，分别遵守对应规则。
- 任务归档、恢复与真删除权限按下文单独规定。

## 成员离开、重新加入与任务分配

- 进行中项目内，负责人离开后，未归档且未完成的任务自动清空负责人，成为未分配任务。
- 已完成任务保留原负责人，标记为已离开项目。
- 已完成任务重新打开时，原负责人若仍已离开项目，则自动清空；同时记录状态变化和分配变化。
- 项目或任务已归档时，保留原负责人并标记已离开项目，不直接修改只读任务的分配。
- 恢复为可编辑时，若任务未完成且负责人仍不是当前项目成员，则自动清空负责人；若原负责人已重新加入则无需清空。项目与任务均未归档时才视为可编辑。
- 负责人清空不改变任务状态、完成时间、创建人或历史。
- 成员重新加入时仍由管理员添加，默认身份为成员，不自动恢复原管理员身份，也不自动恢复此前已清空或重新分配的任务。
- 重新加入不改写过去的退出及任务分配日志。

## 分配变更日志

- 手动指定、更换、清空负责人以及成员离开、恢复或重新打开时导致的自动清空，均记录日志。
- 日志包含操作时间、具体任务、前后负责人和操作人；自动处理注明触发原因并关联实际触发人。
- 分配日志的展示遵守 [操作记录模块](06-history-and-exceptions.md)；保留与删除遵守既有任务、项目历史规则。

## 任务归档与恢复

- 项目管理员和普通成员均可归档、恢复本项目任意任务，未完成任务也可归档。
- 归档为可恢复的软删除：从默认看板和任务列表收起，在归档列表查看。
- 常规任务看板默认只显示未归档任务；用户主动进入项目内归档任务列表时查询归档任务，不提供默认开启的归档展示。
- 归档保留任务状态、负责人、正文（含图片）、评论及历史，任务和评论只读；成员仍可阅读正文及查看图片。
- 完成表示工作做完，归档表示收起备查，两者相互独立。任务可以已完成且已归档，也可以未完成且已归档。
- 完成不自动归档或变为只读；归档和恢复不改变原任务状态、完成时间，也不等于完成或重新打开。
- 恢复后重新允许正常操作，任务放回原状态列末尾，状态和完成时间不变；负责人按上文成员离开规则处理。
- 归档任务仍保留所属状态列；删除列时必须计入归档任务，具体遵守 [看板列删除保护](03-boards-and-workflow.md)。这不改变归档任务默认隐藏的展示规则。
- 任务归档、恢复要求项目处于进行中；项目归档后不能单独归档或恢复其中任务。
- 恢复项目保留各任务原有的归档标记，不自动恢复单独归档的任务；仍归档的任务继续隐藏并只读。
- 更换完成列时，原、新两列也必须没有归档任务，不能通过归档绕过空列约束。

## 任务真删除

- 仅该项目管理员可以真删除任务，未归档或已归档任务均可直接删除，无需先归档。
- 删除前展示删除范围和不可恢复含义，二次确认后执行；取消时不删除。
- 真删除同时删除任务、其评论及任务内历史日志，不提供应用内恢复；不再被有效正文使用的图片按 [资源清理规则](07-images-and-resources.md) 清理，仍被其他内容引用的图片不得误删。
- 保留项目共用标签和其他任务。
- 任务真删除要求项目处于进行中。管理员仍可按项目模块规则直接真删除整个归档项目。
- 项目记录保留被真删除任务的标识、当时标题、删除人和时间，不保留正文；删除整个项目时一起清除，见 [操作记录模块](06-history-and-exceptions.md)。

## 系统自动记录的信息

- 系统自动记录创建人、创建时间及最后更新时间，用户不能手动修改。
- 编辑任务不改变其创建人和创建时间。
- 任务字段、状态、负责人、标签关联及归档恢复实际变化更新最后更新时间；查看、排序、评论或无变化保存不更新，评论单独记录时间。
- 稳定任务编号格式如 `#0001`；全应用唯一递增、最少四位及溢出规则采用整理默认 R01，详见 [字段规则](10-fields-and-ui.md)。

## 自定义标签

- 支持用户自定义任务标签。
- 标签在当前项目内共用；每条任务可关联多个标签，也可以不设标签。
- 项目管理员和普通成员均可创建标签；重命名与删除标签由项目管理员执行。
- 删除标签时移除任务上的对应标签关联，保留任务及其状态。
- 标签作为独立于任务状态的筛选维度，不参与看板列的排布。
- 设置或修改标签不改变任务所属列、完成含义或完成时间。
- 项目管理员和普通成员均可在本项目任意可编辑任务上应用或移除项目标签。标签名去除首尾空白后不能为空，同项目内英文忽略大小写判重。
- 标签创建者可选颜色，不选使用默认；后续仅管理员可改色。颜色不参与看板排列或完成判断。
- 标签在项目任务查询中筛选，多选标签按任一匹配，与其他维度及关键词同时满足；具体见 [查询模块](05-query-and-my-tasks.md)。

## 任务描述与评论正文格式

- 任务描述与评论正文均支持 Markdown 格式，保存后可按格式阅读。
- 任务描述仍为选填，评论不能是空内容；允许纯图片评论，但至少有一张上传成功、取得链接并插入正文的图片。空白内容或未完成上传的占位图不算有效评论。
- 任务与评论取消独立附件功能，内容采用 Markdown 文字与正文图片，不提供通用文件附件管理。
- 统一支持标题、粗体/斜体、列表、引用、链接、代码块和表格。
- 编辑时可切换源码与预览，保存后显示 Markdown 排版结果，再次编辑保留原始格式。
- 编辑与渲染优先复用成熟第三方库；具体选型在生成实现阶段适配 Kooboo，不要求自研编辑器。
- 引入第三方库仍须满足正文图片链接化、项目权限和持久化要求。
- 描述与评论支持输入 @搜索选择当前项目成员，按用户标识关联并在保存后向有效接收人通知；编辑只通知新增提及对象，去重及权限规则见 [通知模块](06-history-and-exceptions.md)。

## 正文图片与链接存储

- 任务描述与评论正文支持插入图片并在正文内展示。
- 插入本地图片时先上传，取得可引用链接后再插入 Markdown 正文；保存的正文只引用图片链接。
- 持久化正文不得包含 Base64 图片数据或 data URL，不能把临时本地预览地址当作最终图片地址保存。
- 图片沿用项目成员访问边界，离开项目后不因仍持有链接而保留访问权。
- 项目或任务归档后正文只读，成员仍可阅读正文和查看图片。
- 支持选择、粘贴及拖入图片，格式为 JPG、PNG、WebP、GIF，单张不超过 10 MB，可点击放大预览；上传失败重试、正文编辑权限及清理遵守 [正文图片与资源清理](07-images-and-resources.md)，不套用旧独立附件权限。

## 任务评论

- 支持任务内评论，用于沟通进展与补充说明，按时间排列。
- 评论正文支持 Markdown 文字和图片，不再设置独立附件列表；评论不能为空。
- 项目管理员和普通成员均可查看、发送本项目任务的评论；非成员及已离开项目的用户不能访问。
- 评论正文仅作者可编辑；作者和项目管理员可删除评论，管理员不能直接改写他人正文。
- 项目或任务归档后评论只读，成员可阅读并查看正文图片，不能发送、编辑或删除评论。
- 评论新增、编辑、删除均留事件记录，日志不备份评论全文或图片；删除评论后不从历史重新展示正文。正文图片清理遵守 [资源规则](07-images-and-resources.md)。

## 可观察的预期结果

以下为已确认规则的验收表达，不扩展功能范围：

- 任务标题不能缺少；描述、负责人及截止时间可以不填，未选择优先级时为普通。
- 每条任务最多一名负责人，不能选择非当前项目成员。
- 截止时间可不填；填写时须有日期、时间与明确时区，不能只填日期并隐式推迟到当天结束。
- 超过截止时刻的未完成任务显示逾期，各成员虽看到不同当地时间但结果一致；已完成不显示，重新打开后重新判断。
- 管理员和普通成员均可创建任务，并编辑由其他成员创建或负责的任务字段、应用或移除标签、调整或清空负责人。
- 负责人不能设置为非当前项目成员；项目归档后不能执行上述任务创建、编辑与分配操作。
- 创建任务后自动显示创建人、创建时间及最后更新时间；这些信息不能手动修改，后续编辑不改变创建人或创建时间。
- 管理员和成员均可创建当前项目共用的标签；任务可没有标签或有多个标签，并可用标签筛选，标签变化不改变看板列及完成状态。
- 普通成员不能重命名或删除项目标签；管理员删除标签后，任务上的关联被移除，任务及状态保留。
- 任务与评论均不出现独立附件管理；图片在相应正文内展示。
- 插入本地图片时先取得上传返回的链接，保存后重新打开正文，图片仍能通过该链接显示；持久化正文不包含 Base64 或 data URL。
- 非项目成员及已离开项目的用户不能通过图片链接绕过项目访问边界。
- 管理员和成员均可归档任意未完成或已完成任务；归档后默认看板和列表不再展示，可在归档列表查看，任务及评论不能修改，但正文图片仍可按权限查看。
- 归档和恢复前后任务状态及完成时间一致：归档未完成任务不使其完成，归档已完成任务保留原完成时间，恢复不等于重新打开。
- 项目处于进行中时，管理员可二次确认后真删除未归档或已归档任务，其评论及任务内历史同时删除；共用标签和其他任务保留，图片按有效引用清理。普通成员不能执行真删除。
- 项目归档后不能单独归档、恢复或真删除其中任务；管理员删除整个归档项目继续按项目规则执行。
- 进行中项目内，成员离开后，其未归档且未完成任务的负责人为空；已完成任务保留原负责人并显示已离开项目，状态、完成时间及创建人不变。
- 已完成任务重新打开时，仍已离开项目的原负责人被清空，状态及分配变化均可在日志中核对。
- 项目或任务归档期间，成员离开不直接清空负责人；恢复可编辑时，未完成任务若负责人仍已离开则自动清空，原负责人已重新加入时保留。
- 成员重新加入后为成员身份，原管理员身份不会自动恢复，已清空或已转交的任务也不会自动重新分配给该成员。
- 手动指定、更换或清空负责人及自动清空，均可在日志中核对操作人、时间、任务、前后负责人；自动处理可核对触发原因。
- 新建任务位于所选列末尾；恢复归档任务后回到原状态列末尾，不改变状态或完成时间。
- 恢复项目后，原本单独归档的任务仍保持归档，不出现在常规看板，也不能编辑。
- 任务描述及评论正文中的标题、粗体/斜体、列表、引用、链接、代码块及表格可按格式阅读；编辑时可切换源码与预览，保存后重新编辑仍保留原始格式。
- 项目成员可发送 Markdown 评论并在正文插入图片，评论按时间排列；至少含一张上传成功、取得链接并插入正文图片的纯图片评论可以发送，空白或仅含上传占位图的评论被拒绝。
- 评论作者可编辑自己正文或删除自己评论；普通成员不能编辑、删除他人评论，管理员可删除他人评论但不能改写正文。
- 项目或任务归档后，评论及正文图片仅可阅读查看，不能继续发送、编辑或删除评论。
- 不提供子任务层级或跨项目移动入口，任务始终属于其创建时的项目。

## 字段与展示补充

- 标题去除首尾空白后必填，任务标题可重名；技术长度上限合理设置并提示，评论与描述同样不静默截断，采用整理默认 R04。
- 卡片展示标题、编号、负责人、优先级、截止时间及标签；任务列表点击任务行或标题打开详情抽屉（drawer），提供字段编辑、描述、评论和操作记录，时间带明确时区，归档任务只读。
- 桌面支持拖拽，手机提供不依赖拖拽的状态入口及查看、新建、编辑、评论和通知；具体见 [字段与界面规则](10-fields-and-ui.md)。
- 字段与评论日志、并发规则见 [操作记录模块](06-history-and-exceptions.md)。
