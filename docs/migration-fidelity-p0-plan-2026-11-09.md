## P0-1 迁移资料补上“视觉层”

目标：迁移场景下，当内容站就是视觉参考站时，生成端能拿到原始页面结构、原样式和加载完成后的双端截图，按“移植原模板”而不是“重新设计”的方式生成。

### 采集引擎（Python）

1. `assets.py` 的 `collect_css_images` 读取 CSS 时保留原始字节：写入 `site/styles/{序号}-{文件名}.css`，并生成 `site/styles/index.json`（`url`、`sha256`、`size`、`pages`、`imports`、`status`）。仍然只解析其中的图片引用；字体和 JS 只登记，暂不下载。
2. 新增模板聚类：按 DOM 骨架签名（去掉文本后的标签和 class 路径哈希）把 574 页分组；每组导出 1–3 个代表页原始 HTML 到 `site/templates/{模板名}/{pageId}.html`，并生成 `site/templates/index.json`（模板名、路径规则、成员数、代表页、签名）。不导出全部原件，避免资料膨胀。
3. `render.py`：模式 B 且内容站等于参考站时（新增 `--visual source` 参数），README 改写为“视觉以 `site/templates`、`site/styles` 与 `site/source-rendered/visual` 为准；复用原 DOM 骨架与 class，套 Kooboo 数据绑定；不得自造配色、字体或区段”。`--visual none` 保持现有文字，不影响非迁移场景。
4. 版本：引擎版本号升级，固定 Python 离线回归覆盖：CSS 保留字节与哈希、相对 `@import`、读取失败仍记 gap、模板聚类结果稳定。

### 平台（Node）

5. 来源渲染截图扩展为视觉基线：`source-rendered.ts` 新增 `captureSourceVisualBaseline`，对每个模板代表页按 desktop 1440 和 mobile 390 拍整页截图，保存到 `site/source-rendered/visual/{模板名}/{viewport}.png`，绑定页面身份、原件哈希和引擎版本。截图使用 P0-2 的稳定化流程。
6. 已冻结快照不能原地修改。对 manwei 现有快照 `bff2871d` 走正式来源修订：只做定向补采（8 份样式表加约 6–10 个代表页截图），不重新全站采集，生成新快照版本，原快照、清单和报告保持不变。
7. `collection/store.ts` 导入素材时增加 `site/styles/**`、`site/templates/**`、`site/source-rendered/visual/**`。`.work/` 仍不导入。
8. 生成预检：迁移且参考站等于内容站时，如果快照缺少视觉层，`preflightCollectionTarget` 返回明确的 `blocked` 原因“缺少视觉基线，需先补来源修订”，不再让生成端自行设计。

验收：

- 用 manwei 冻结原件离线运行，得到 8 份 CSS（含 `common.css`、`swiper.css`）和首页/分类列表/案例列表/详情/地图等模板分组，代表页 HTML 哈希可回指原件。
- 新快照导入后，生成端可通过资料映射清单读到样式、模板和视觉截图；README 不再出现“不要还原外观”。
- 不改变 81 项已接受素材缺口，不改变 574 / 381 / 102 / 1044 等冻结集合。

## P0-2 参考基线冻结与截图稳定化

目标：每轮评测和修复引用同一份参考画面，不再出现“这轮看到空白、下轮看到轮播”的情况。

1. `browser.ts` 截图前增加有上限的稳定化流程 `settle(page)`：等待 `load`（上限 15s）、网络空闲（上限 8s）；逐屏滚动到底触发懒加载后回到顶部；等待视口内 `img` 解码完成（`decode()`，上限 5s）；最后额外等待 1s，让轮播首帧到位。观察结果新增 `settled`、`pendingImages`、`blankImageRatio`。
2. 参考角色的截图如果 `settled=false` 或视口内超过 30% 的图片未加载，浏览器服务直接返回错误让模型重试，最多重试 2 次；重试仍失败时保存为 `reference-unsettled`，不允许作为视觉评分证据。
3. 迁移评测优先使用 P0-1 冻结的视觉基线：`evaluator.ts` 把基线截图作为 `reference-baseline` 角色放进 `materials`，`visualEvidenceContract` 要求视觉项引用基线或稳定化后的参考 PNG。评测仍可现场拍参考站，但结论与基线冲突时必须在 reason 中说明并引用两张图。
4. 校验：`validateResult` 拒绝引用 `reference-unsettled` 的视觉判断。

验收：

- 固定一个带懒加载轮播的本地夹具页：不加稳定化时截到空白，加了之后截到首帧；未加载完成的截图被拒绝。
- 连续两次评测同一修订，首页 Hero 项对参考站的描述一致（以基线截图为准）。

## P0-3 程序差异按模板与片段归并

目标：报告和修复委托先说明“哪个模板缺了什么、影响多少页”，而不是“566 页失败”。

1. `target-verification.ts` 在截断到 8 个片段之前，按完整缺失集合累计：
   - 模板：路径规则优先使用 P0-1 的 `templates/index.json`，没有时退回路径模式（`/cn/show/{id}`、`/cn/category/{id}`、`/cn/category/{id}_{n}.aspx` 等）。
   - 键：`(模板, 差异类型, 归一化片段或链接模式)`，差异类型分为文本、链接、分页导航。
   - 输出 `defectGroups: [{template, kind, key, pages, templatePages, samplePaths(≤5), evidence}]`，按 `pages` 降序。
2. 报告新增“模板覆盖率”视图：每个模板的通过页数 / 总页数，以及前 5 个缺陷组；保留逐页明细作为完整证据。
3. 评分说明：评测的 completeness 判断引用 `defectGroups` 和模板覆盖率，不再只引用“通过页数”。权重本身暂不调整，单独讨论。

验收：

- 用 `0ed1116d` 的已保存证据离线重算：得到 `详情模板 / [ 返 回 ] / 362 页`、`详情模板 / 官方网站 / 168 页`、`分类分页 / « / 135 页` 等分组，与本文统计一致。
- 所有失败页都至少归入一个分组，没有遗漏或重复计数。

## P0-4 修复委托裁剪与可信事实

目标：委托短而可执行，影响最大的问题排在最前面；关于参考站的断言必须有冻结依据。

1. `collectionTargetRepairContext` 改为输出：`defectGroups` 前 15 组 + `confirmedTargetFailureCount` + `verificationGapCount` + 一句话边界说明。去掉与 `confirmedTargetFailures` 重复的 `checks` 列表；长段 guidance 移到生成端 SKILL / 资料文件，委托里只留一行引用。完整差异写入 kfile，委托给出路径。
2. 规划 Agent 提交 `repair` 时，每个修复项必须带 `source`：`program-group`（引用 defectGroup key）、`report-issue`（引用报告问题序号）或 `baseline-visual`（引用基线截图）。凡是“删除 / 不得新增 / 参考站没有某区段”这类否定性视觉指令，必须引用 `baseline-visual`；只引用现场参考截图且与基线冲突时，宿主拒绝该项并返回原因。
3. 委托上限：正文 ≤ 12KB（不含图片），超出部分自动转为 kfile 附件。
4. 规划 Agent 图片输入改为降采样：宽度缩放到 ≤1280px，转为质量 80 的 JPEG，单轮合计 ≤ 6 MiB；窗口续接时不重复附加同一会话已发送过的图片。解决本轮 3 次 `413 Payload Too Large`。

验收：

- 用 `df3c3551` 报告离线生成委托：正文 ≤ 12KB；前 5 组覆盖 `[ 返 回 ]`、`官方网站`、分页箭头和首页场景区。
- 构造“参考站无 Hero”的否定指令，仅引用现场参考图且与基线冲突时被宿主拒绝。
- 规划请求总字节在图片 20 张时 < 10 MiB。

## 本轮复评中额外发现的平台缺陷（随 P0 一并修）

1. **重新评测继承了过期清单**：`/api/automation/tasks/:id/followup` 创建评测时沿用父任务的 `requirementsId`。`b055a7ee` 仍指向修订 1 的 `67f80d08`，而原评测已经补全为修订 2 的 `e89c6c42`。新版核验器拒绝修订 1，复评 `6f4c01b4` 在请求评分模型前就中断。修复：创建评测时，如果父任务的当前报告绑定同一输入版本、站点和采集版本，并且报告清单更新，就采用报告清单。本次临时改为以 `fd34ac68` 为父任务发起复评 `b859d53e`。
2. **契约失败仍触发经验复盘**：`6f4c01b4` 没有请求评分模型，却启动了一次经验复盘。修复：评测在模型请求前因契约或预检失败时不进入复盘。
3. **取消修复后报告失效且无提示**：`cad564f7` 取消后站点修订变化，旧报告失效，列表只显示“暂无有效报告”。修复：取消已动过站点的修复时提示“需要复评”，并在站点行展示原因和一键复评入口。

## 实施状态（2026-11-09）

三批代码均已完成，针对性测试、服务端类型检查和构建通过；真实模型生成、manwei 来源修订和视觉验收尚未执行。与上文方案的偏差：
