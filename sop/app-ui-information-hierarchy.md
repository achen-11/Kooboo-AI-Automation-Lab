# AI App 信息层级与交互审查参考

参考版本：`app-ui-quality-v1.1`；更新日期：2026-11-09。

本参考来自 Automation Lab 的实际使用反馈，用于编写自定义生成要求与评测 SOP / references。发布规则时选择适用指标并设置权重；既有任务继续使用其冻结快照。

本文件是可复用的规范来源，不代表平台已自动注入或执行这些检查。资料包应携带所用版本的完整快照；生成与评测采用同一快照。业务场景决定页面组织，具体像素、框架和组件由实施方合理选择。

## 生成要求

- 从用户最常见的任务组织页面。首屏应能识别对象、当前状态、关键结果和下一步，默认只呈现完成此任务需要的信息。
- 区分查看、创建和编辑。以阅读为主的详情默认展示可读内容，编辑入口明确；高频字段可就地编辑。不要将详情中的全部内容默认变成输入框或源码编辑器。保留业务确需持续录入的工作流。
- 空间分配服从内容与操作。复杂长内容在宽屏应有足够阅读空间，属性与正文合理分区；窄屏重新组织。抽屉、弹窗、侧栏和遮罩应服务当前任务，不规定所有应用使用同一布局或固定宽度。
- 列表支持扫描，突出对象名称和判断所需字段。避免重复展示已由分组表达的信息、给每行堆放全部编辑控件，或让空状态插画挤占主要内容与操作。
- 从列表打开详情再返回时，保留合理的筛选、排序和滚动上下文；数据变化使对象不再匹配时，准确更新结果并解释必要变化，不伪造仍在原位。
- 保存、取消和关闭的含义一致。未保存退出须有明确处理，失败保留输入并提供重试；成功反馈与实际持久化一致。不能只根据按钮或提示存在判定交互通过。
- 对复杂详情页按用户目的分区；身份与必要操作保留在公共头部，日志、用量、配置等进入对应区域。不要把新增功能持续堆在 tabs 之前。
- 业务结论与执行状态分开。例如“执行完成”不等于“质量通过”；失败、未验证、数据缺失不能显示为成功或零值。
- 摘要、完整说明和技术诊断分层。通知说明对象与事件，并指向详情；不要直接复用完整 AI 输出、调用栈或内部 ID 作为正文。
- 大列表使用服务端分页或有界增量加载。页面首次进入和后台刷新只请求需要的数据；切换分区后加载对应内容，过期请求不能覆盖当前对象或筛选结果。
- 将图像与证据放在支持具体判断的位置；大量图像按需加载。折叠视觉内容不等于停止请求，需核对实际网络行为。
- 操作放在其所属上下文，区分主要动作、次要动作与运行控制。按钮之间、按钮与相邻内容之间应有统一间距；窄屏可合理换行，不能重叠、挤压文字或造成页面横向溢出。
- 展开、收起、分页等使用一致图标与明确的点击区域；提供可访问名称、展开状态、键盘操作、加载状态和错误重试。
- 历史异常可追溯，当前状态应明确。恢复后保留原异常记录，同时避免将旧通知显示为仍在发生的故障。

## 评测方法与证据

| 观察点 | 检查行为 | 应记录的证据 |
| --- | --- | --- |
| 首屏阅读层级 | 从列表进入真实详情，判断能否快速找到状态、结果和下一步 | PC / 移动端首屏截图及具体位置 |
| 查看与编辑 | 读长正文，再编辑、预览、保存和取消 | 各状态截图、实际值及操作记录；不能从静态截图推断保存行为 |
| 空间与内容适配 | 检查长名称、表格、图片、多属性、多评论和无数据状态 | 对应数据状态、视口、截图及遮挡/溢出位置 |
| 连续工作 | 带筛选和滚动打开详情，修改后关闭，再打开另一对象 | 返回前后条件、顺序和位置；对象退出匹配条件时的结果 |
| 复杂信息分区 | 切换各页签、展开诊断，核对任务上下文 | 切换前后截图、可访问快照 |
| 长列表 | 使用足够多的实际记录，翻页、筛选并返回 | 页码与总量截图；请求参数、返回条数或性能记录 |
| 按需加载 | 进入页面、切换区域、展开证据并等待刷新 | 对应请求 / 返回大小；仅有截图时明确网络行为未验证 |
| 操作布局 | 检查常见桌面宽度与窄屏、长名称、多个可用动作 | 截图中的间距、对齐、可点击区域与溢出位置 |
| 异常恢复 | 查看真实或测试异常，恢复后再查看历史 | 当前状态与历史记录的对应证据，不执行不可逆动作 |
| 可访问性 | 尝试键盘切换、聚焦和展开 | 实际操作记录、可访问名称与状态 |

审查页面是否支持用户完成任务，不按卡片数量、字数或空白面积机械扣分。高密度表格可以合理；关键是信息是否分组、可扫描、可操作。缺少长列表、异常或网络证据时标记未验证，不将通用经验当作当前 App 已发生的缺陷。

## 生成与评测检查点

1. 实现前，依据业务场景形成主要页面、内容分区、查看/编辑状态、关键操作及异常反馈的简明方案，并自行审查。只有业务取舍、需求冲突或影响较大的未知项才提交用户确认，不逐个按钮要求审批。
2. 实现后，在获授权的环境和身份下检查真实页面及操作。分别记录功能是否具备、交互是否可用；用长内容、多记录、空数据、失败和窄屏状态复查，修复后重新核验对应场景。
3. 独立评测基于同版业务需求与本参考快照，另行取证。生成者自测声明保留来源，不直接等于独立通过；截图支持视觉判断，行为判断须有操作及结果证据。
4. 无有效身份、测试数据或其他前置时，记录受阻范围与待补条件。预期的登录保护不等于业务失败；有效身份仍无法登录时，另查认证流程是否有缺陷。
5. 每个问题记录场景、视口、测试身份代号、站点修订、证据、用户影响、修复及复查结果。缺少证据时写未验证；现有任务不追溯套用后发布的新要求。
