# AI App 界面生成与评测接入方案

日期：2026-11-09。状态：已确认方法，文档已整理；本文件所述自动接入尚未实施。

## 职责与输入

| 层面 | 负责内容 | 本次产物 |
| --- | --- | --- |
| 平台通用要求 | 信息层级、阅读编辑状态、空间适配、连续操作、反馈与一致性 | [UI 质量参考](app-ui-information-hierarchy.md)，版本 app-ui-quality-v1.1 |
| 当前业务资料 | 用户目标、典型工作过程、内容规模、关键交互与业务约束 | 任务看板资料包的使用场景模块及隔离测试资料 |
| 生成与独立评测 | 方案自审、真实操作、自测、独立取证、修复复查 | 下述待接入流程；文档存在不代表执行器已有此能力 |

业务资料不要求用户先画完所有页面或指定所有尺寸。生成器应主动组织界面；通用质量问题由统一方法持续改进，业务特殊偏好留在对应资料包。截图可以说明问题或提供参考，只有用户明确指定时才作为复刻目标。

## 待接入生成流程

1. 冻结业务资料、通用 UI 规范快照及其版本/哈希，记录实际输入清单。发布新要求不修改旧运行的预期。
2. 生成器在实现前形成可审查的关键页面方案：主要工作、内容分区、查看/编辑状态、保存返回行为、窄屏及异常状态。先自查需求覆盖和使用路径；仅将真正影响业务的取舍交用户确认。
3. 实现后在获授权的测试身份和数据下执行自测，分别报告功能结果和体验结果。发现问题后修复，并留下对应复查证据。
4. 交付时提供实际页面方案、自测结果、问题与限制，以及独立评测可使用的站点修订和测试前置说明。密码、令牌和会话材料由平台管理，不写入资料包或模型可读报告。

## 待接入独立评测流程

1. 检查目标站身份及业务页可访问性，再执行该身份允许的业务。未登录访问保护与已登录业务验收分别记录；认证前置缺失时标记受阻，不批量把受保护页面判为业务缺陷。
2. 按场景使用独立测试身份。管理员页面通过不能替代普通成员、非成员、未登录以及多人通知的验证。
3. 同时采用截图与实际操作证据。功能存在、视觉可读、行为可用分别判断；保存与持久化等行为不能仅靠截图证实。
4. 输入中的空白结果模板、生成者自测记录、独立评测结果分别保存并注明来源。模板的未执行不证明生成者没测，自测声称通过也不替代独立取证。
5. 问题绑定输入版本、站点修订、身份代号、视口与证据。修复后复查相关场景，保留原结果，避免只反复截图而不检验行为。

## 后续实施边界

- 需要核对规范快照如何进入生成与评测输入、检查点如何持久化，以及现有浏览器工具能否完成所需操作。
- 需要验证 Kooboo 正式认证方式、目标站可接受的登录态及域边界，再设计身份注入、过期续接和会话隔离。不能假定管理端令牌可直接用于所有目标站。
- 当前仅形成资料及接入方案，未改生成提示构建、评分规则发布、认证或浏览器执行代码，未上传新版本或启动新运行。
