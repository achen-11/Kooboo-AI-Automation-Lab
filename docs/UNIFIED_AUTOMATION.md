# Kooboo AI Automation Lab

本轮按 2026-11-07 确认的讨论方案实施。默认进入任务中心，界面沿用 CPR，图标使用 Lucide；侧栏支持收起 / 展开并记住状态，所有页面共用 Select 组件。

## 任务详情与信息层级

- 任务中心以生成站作为一行，生成、跟进、独立评测、续建与修复归入同站；未创建站点的任务单独保留。主列表直接显示当前交付状态、当前版本分数和站点累计成本。资源与站点为一对多，不按资源名或 URL 合并。
- 站点费用从关联任务的原始请求账本汇总，不相加已包含子任务的流程小计。详情可按需展开生成、跟进、评测等阶段成本和分页执行历史；用量页默认查询整个生成站的请求，保留未知费用提示。执行结束不表示可交付，首页达标不代表全站完整。
- 任务中心进入默认“概览”。五个分区为概览、评测结果、执行记录、用量费用、输入与配置；具备能力的连接额外展示交付。侧栏不再单列评测报告，“评测结果”按生成站汇总初评、自动优化复评、手动重评及续建评测，按创建时间倒序，每页 10 条，只查询摘要。点击记录在同一分区查看报告，返回保留列表页码；当前结果和历史报告明确区分，尚无报告的执行仅显示状态。
- `#/tasks/:id?tab=report&view=history` 进入该站评测记录，`&report=:evaluationId` 定位报告；评测任务原有 `?tab=report` 链接仍直接打开该报告。资源卡片进入该站评测记录，任务中心分数直接进入对应报告。原 `/reports` 和 `/legacy-evaluations` 路由仍作为历史兼容入口，完整报告、证据和对外 API 保留。轮询不切换所选分区，不将修改前或仅首页报告用作当前全站结果。
- 概览分别展示生成与评测执行状态、质量摘要、当前需要处理的事项、进展及费用摘要。完整 AI 原因、历史尝试与跟进计时放在执行记录。恢复按钮作用于需要恢复的原任务；“更多”中的生成跟进 / 重新评测创建新一轮任务。
- 用量明细和执行日志由服务端每页返回 20 条；用量支持阶段筛选。计费口径、原始 usage、完整上下文与版本标识通过 Lucide 展开控件查看。错误、待核算和未验证状态仍明确显示。
- 评分、问题及覆盖缺口在所选报告详情中展示，并标明实际评测范围与时间，使用该次评测冻结的规则。问题可展开其证据；全部截图默认关闭，每页 12 张，仅展开后加载图片。报告未变化时不因每次轮询重复读取全文。
- 通知呈现任务名、事件与短摘要，点击进入任务分区。历史异常若已有后续进展会标注，完整诊断可从执行或交付记录查看。
- 新 UI 使用 `GET /api/automation/tasks/:id/summary`，`/usage?page=1&pageSize=20&stage=evaluation` 和 `/sections/{execution,input,report,delivery}`；execution 接受相同分页参数。任务列表与通知选择 `?view=compact`。原本完整详情、通知和外部报告 API 保留其数据契约。
- 同站评测摘要使用 `GET /api/automation/site-deliveries/:id/reports?page=1&pageSize=10`，报告详情使用 `/reports/:reportId`；详情校验评测确实属于该生成站，不按资源或 URL 推测关联。这两个本地管理接口使用本机会话，对外查询继续沿用已有读取令牌接口。
- 可复用的 AI App 生成与评测观察点见 [信息层级审查参考](../sop/app-ui-information-hierarchy.md)，可纳入自定义 SOP / references；本次不改写已发布规则或历史评分。

本轮已通过平台类型检查、构建与接口回归；界面视觉及具体交互效果需由用户在 4180 验收，未以浏览器控制或截图模拟替代。

评测恢复保留原任务、站点、规则和经哈希校验的证据。Kooboo 生成会话与 Codex 评测会话独立保存，生成执行检查不会覆盖评测线程。明确的图片请求 / 上下文超限或本地 rollout 缺失会解除失效评测线程，供 AI 跟进选择在新会话中复用证据重试。图片评测 / 交付用量转发的请求体上限为 128 MiB，流程跟进为 32 MiB；超限保留明确错误，不无限增大请求。

评分输出先校验每条视觉指标的同视口 target PNG，以及存在参考站时的 reference PNG。校验失败把全部缺失指标 / 视口 / 角色反馈到原 Codex 会话，附最新证据清单，最多追加两次结果修正；失败记录和用量保留，持续失败再交流程跟进。宿主不自动改写分数或替 AI 配证据。评测恢复会直接传入跟进 Agent 查明的原因与要求，避免无反馈地重复整轮。

## 使用

1. 系统设置 → Kooboo 连接：填写环境名称与地址，点击“登录连接”，使用账号密码及必要的验证码自动获取并加密保存访问凭据。已有令牌可在“手动填写访问令牌”中录入并保存，再测试连接；过期后可重新登录。连接后可从该环境的可用域名中选择“默认建站根域名”，保存后用于后续新建任务。
2. 系统设置 → 评测模型：同一卡片填写模型名称、API 地址和 API Key，统一保存，再测试图片识别与工具调用。默认模型 `deepseek-flash-1017`；API Key 留空保留已有加密密钥。首次显示实际生效的 API 基础地址，兼容已有 `/chat/completions` 或 `/responses` 地址。原评分执行器配置在后台兼容保留，不再作为第二张配置卡片展示。
3. 资源库：填写自由说明、需求、内容站 / 参考站和附件。无需 README 或固定文件格式。单文件上限 16 MB；外部来源与标识成对填写。
4. 在资源表勾选 checkbox 批量创建任务；创建窗口选择范围、环境、建站根域名及补充要求，并可预览委托消息。单资源新建可填写站点名称与子域名；留空时沿用资源配置或自动生成。根域名优先带入资源的导入配置，其次使用环境默认值；批量资源可保留各自的域名配置，也可统一覆盖。任务入队时固定输入版本和所选域名，网络重试使用同一请求标识。已有站点继续生成与评测沿用原域名。
5. 在系统设置启用自动执行。队列默认暂停；生成和评测分别受全局并发上限控制，生成页面由服务保持运行，管理页关闭不影响任务。
6. 生成结束后默认交接独立评测，可在设置关闭。自动评测沿用本次生成的输入版本、范围和同一生成站；缺少公开地址时记录原因，不虚构报告。
7. 资源详情保留多个生成站；可在既有站继续生成，选择全站范围用于首页样稿之后的续建，也可关联已有站点后评测。
8. 任务详情查看真实委托、状态、执行事件、AI 跟进动作及最近上下文。准备、生成、交接或评测异常时自动进入内置 AI 跟进；无法继续时交付中断说明。历史已停止任务可点击“AI 接管 / 恢复”，沿用原任务、生成站和证据。手动“提交跟进 / 重新评测”仍会创建新一轮任务。
9. 系统设置 → AI 跟进：调整启用开关、独立并发、次数、时间、token 预算及 SOP；跟进与评测复用现有模型配置。查看侧栏通知箱获取完成报告与中断结果，可按需启用浏览器桌面通知。

建站前会再次校验任务固定的根域名；不可用时中断并说明原因，不自动换域名。站点名称和子域名优先使用创建任务时的 `siteName` / `subDomain`，其次沿用固定资源版本的同名配置。只指定一项时另一项默认使用该名称；都未指定时才使用 `auto_<任务 ID 前 12 位，连字符替换为下划线>`。名称允许英文字母、数字、下划线，统一为小写；自定义名称或子域名被占用时，为被占用的字段添加 `_1`、`_2` 等后缀并保存最终选择。最终公开地址仍从 Kooboo 返回的站点信息取得。“输入与配置 → 建站配置”可查看任务实际采用的站点名称、子域名和根域名。创建请求前固定实际名称与子域名；升级前结果不确定的旧任务仍按旧名称核对原站，禁止重复创建。

本地管理接口 `GET /api/environments/:id/domains` 读取已保存连接的 `Domain/Available`，返回 `{ items: [{ domainName, sudDomainUseDash }] }`。环境配置可选 `defaultRootDomain`（空字符串表示清空默认值）；`POST /api/automation/tasks` 支持可选 `siteName`、`subDomain`、`rootDomain`，仅供新建生成站使用；前两项只允许用于单资源请求，批量时请在每个资源中独立配置。根域名按本次请求、固定资源版本、入队时的环境默认值依次取值；都未配置时在首次执行固定可用列表首项。已有站点的续建与评测不应用这些建站默认值。

Kooboo 的香港根域名可能返回 `-shawnchen-hk.kooboo.io`，前导 `-` 已经是分隔符。拼接 `salon_demo` 的结果必须是 `salon_demo-shawnchen-hk.kooboo.io`；不得再加一个 `-` 或插入 `.`，也不得把 `shawnchen-hk` 并入用户子域名。回填和换绑按完整可用后缀匹配；旧配置省略前导 `-` 时可匹配同一根域名，但向 Kooboo 创建和绑定时使用其实际返回值。根域名不可包含协议、端口或路径。

## 评测规则与证据

- SOP、参考资料、指标、权重、适用场景、范围、视口及必过项可编辑。保存并启用生成不可变版本，任务固定实际规则，新规则不改写历史。
- 草稿可保存在当前浏览器，未启用前不参与评分；这不是跨浏览器协同草稿服务。
- 默认 Site 视觉口径使用 Hero 40%、结构 40%、其他区段 20%。迁移 / 升级全站另有完整度、动态内容实现与 SEO 的可编辑初始规则；这些额外比例属于实施默认值。App 初始 UI / 业务比例同样可改。
- PC、移动端、业务分别给分，没有默认将它们合并为一个总分。平台根据适用指标的权重计算各组分值。
- 本地 Codex Agent 按 SOP 使用受任务约束的浏览器工具取证；管理平台不把页级图片诊断计数直接解释为视觉缺陷。
- 有分数的视觉指标必须引用本轮对应视口与角色的真实截图；平台校验证据清单、哈希、指标与范围。不存在的材料不能评分，未验证保留 `null`。
- 动态内容存储 / 路由、复杂业务与正式上线 SEO 缺少实现或实际结果证据时必须标记未验证。当前工具主要提供页面操作和截图，不因此宣称后端实现已经通过审核。
- 网站 UI / 业务操作仅在实际启用任务后执行。评测只审查和交付报告，不自动修复目标站；修复继续进入生成调度。

## 外部 Admin API

首版服务仍绑定本机。现有本地会话、导入与读取令牌沿用加密存储；不修改全局 Codex 配置或原运行数据。其他机器访问、任意外部网页跨域访问和生产认证需后续部署处理。外部服务可以通过 HTTP 接口对接，本机页面提供示例与令牌复制。

| 接口 | 授权 | 用途 |
| --- | --- | --- |
| `POST /api/v1/resources/import` | 导入令牌 | JSON 数组导入；相同外部来源 / 标识保存新的输入版本 |
| `GET /api/v1/automation/tasks?status=pending` | 读取令牌 | 外部 AI 查询任务状态和上下文 |
| `GET /api/v1/automation/reports` | 读取令牌 | 按 externalSource、externalId、resourceId 及分页读取多站多轮评测 |
| `GET /api/v1/automation/reports/:id` | 读取令牌 | 实际任务、固定输入、规则、报告及事件 |
| `GET /api/v1/automation/reports/:id/artifacts/:file` | 读取令牌 | 本轮真实证据，读取时重新校验哈希 |

无报告时 `report: null`，不返回假零分。读取令牌无任务创建、跟进或修改权限；当前跟进操作使用本地管理会话。文件附件先通过本地资源上传；外部 JSON 可使用已存在的附件标识，不能伪造文件元数据。历史评测接口继续可用。

资源导入支持插件版的可选 `siteName`、`subDomain`、`rootDomain`，随资源输入版本保存，在后续新建任务时使用。例如 `POST /api/v1/resources/import` 的一项可写为：

```json
{
  "name": "Latendance Coiffure",
  "scenario": "materials",
  "description": "按资料重建首页",
  "contentUrl": "",
  "referenceUrl": "",
  "externalSource": "admin",
  "externalId": "latendance",
  "files": [],
  "siteName": "latendance",
  "subDomain": "latendance_demo",
  "rootDomain": "-shawnchen-hk.kooboo.io"
}
```

导入本身只保存资源，不启动任务。重新导入不会改写已入队任务的名称或历史输入。创建任务可显式覆盖导入值；同一幂等请求重试仍保留第一次入队时的配置。

这三个字段均可省略；未指定时不要传空字符串。`siteName` 与 `subDomain` 只允许字母、数字和下划线，最多 63 个字符；`rootDomain` 允许香港根域名的前导 `-`，也兼容省略它的写法。请求头使用 `Authorization: Bearer <资源导入令牌>` 和 `Content-Type: application/json`，请求体为上述资源对象组成的 JSON 数组。

资源详情和每个历史输入版本直接显示保存的站点名称、子域名与根域名；未传入的字段显示“未指定”。根域名在这里不补全前导 `-`，便于核对导入值。输入仍经过原有去空白、小写等校验处理，不是原始 HTTP 请求备份。任务“本轮输入”显示固定版本的值，“建站配置”显示实际采用的配置。

## 中断与恢复

取消请求不立即释放执行名额；执行器完成清理之后才释放。正常失败自动进入内置 Codex 跟进；工具允许查任务、原会话、站点、首页可访问性及真实执行状态，再安排原任务重试、原会话继续 / 回答、交接评测、等待或中断。生成与评测使用独立会话。普通跟进不依据低分修改站点；显式启用的质量优化按以下流程执行。

### 自动优化到目标

AI Site 模板、迁移与升级的新建生成任务，执行目标默认“自动优化到目标”，仍可选择“生成并评测”。默认 PC / 移动端各 85 分、最多修复 3 轮，不包含初次生成与初评；实际取系统已保存的优化设置并冻结。已完成且有有效当前报告的上述任务，可在“更多 → 自动优化到目标”显式启用，沿用原站、原会话、输入与规则。历史低分任务不会自行启动。仅模板使用 imagePlaceholder；迁移/升级保留真实内容及合法资源，完整度、动态实现和 SEO 必过项继续参与停止/达标判断。

站点汇总接口：`GET /api/automation/site-deliveries?page=1&pageSize=20&q=&state=`；单站 `/site-deliveries/:id`、执行历史 `/site-deliveries/:id/tasks?page=1&pageSize=10`、用量 `/site-deliveries/:id/usage?page=1&pageSize=20&stage=evaluation`。使用原本机会话认证。原始任务、当前结果、历史报告及外部 Admin 契约保留；站点汇总不是修改历史报告或承诺正式上线结果。

系统设置可修改默认目标、轮数、可选费用上限和质量分析 SOP；已启动任务使用冻结配置。跟进 AI 接收经哈希校验的双端目标 / 参考 PNG 及报告，整理修复委托后，Kooboo 在原站原会话修改。独立评测重新采集并复评，二者串行。新的 AI Site 模板流程将冻结参考 PNG 及本轮修复问题截图上传到目标站专属的隔离研究 Sandbox（`automation-ref-<siteId>`）媒体库，上传后回读原字节校验哈希；任务包 `referenceImages` 仅保存页面、视口、view、图片 ID、来源 Sandbox（`sandbox`）、来源角色与修订的索引。生成 AI 必须通过 `read_image` 实际看图，上传成功或读到索引不算看图，因此该流程不要求 bridge 支持 `imageInput`。旧流程的直接图片附件仍要求 `imageInput`，缺失时保留明确错误，不静默丢弃图片。

生成侧优先复用已交付截图；需要补图或切片时复用同一研究 Sandbox（或已克隆参考站的研究 Sandbox），使用 `take_screenshot`，长页保持 `fullPage=true` 且不缩放，再通过 `process_image(operation="slice")` 切片，沿 `nextOffset` 续切，并逐段 `read_image`；`read_image` 与 `process_image` 均必须携带索引项给出的 `sandbox`，不写入目标实现站媒体库。Lab 本地采集器的 `take_page_screenshots` 属于独立工具接口，不能将其写成 Kooboo 生成侧的必需函数。参考 PNG 与修复截图按内容哈希存放在研究 Sandbox 的 `/_automation-reference/<基线或报告或输入版本>/`，重启校验后复用；保留供会话继续读取，不随临时 kfile 清理，不用于生成站业务展示。全站分析允许动态模板抽样，但必须保留完整交付路径；发现页面未声明、内部链接未分类或双端研究未覆盖时保存未完成草稿，不得通过删路径声明完整。

概览展示当前阶段与目标；评测结果默认展示当前版本报告，并按轮次查看历史报告、修复要求及改善分析；执行记录和用量支持按阶段 / 轮次查看。任务列表隐藏内部修复子任务，队列统计仍包含它们。首次质量分析初始化独立跟进预算，后续各轮累计，Kooboo 和评测等待不计入该活动时间。
