# Frontend

The active application is Vue 3 + Vite with an independent Node.js server. The SPA uses hash routing and root entry `/`; source lives in `frontend/src/` and shared application types live in `shared/`.

`npm run dev` starts the Node API and background worker at `http://127.0.0.1:4180`. For frontend hot reload, run `npm run dev:web` separately; Vite listens on `http://127.0.0.1:4181` and proxies `/api` to the Node server.

`npm run build` writes frontend assets into `dist/` and compiles readable Node modules into `dist-server/`. `npm start` serves the SPA and API together. Former Kooboo runtime resources have been removed; the old implementation is available in Git history.

Keep the existing page layout, task stages, execution history, screenshot comparison, and site-preview iframe. The frontend establishes the HttpOnly local session automatically through `POST /api/login` when a request receives 401, shares concurrent connection attempts and retries each request at most once. There is no manual entry screen or logout control. Local session checks and trusted-origin restrictions remain in the backend; this is not production user authentication.

Settings include a single configurable image- and tool-capable Chat Completions model, Kooboo environments, review threshold, queue pause, a stage budget for each viewport capture and final scoring, and bounded capture attempts. Keep secret fields empty after saving and retain the existing secret unless explicitly replaced or cleared. Model tests submit actual pixels and validate function calls and tool result consumption.

The active backend is `server/`, contracts are `shared/`, evaluation instructions are `sop/`, and focused tests are `tests-node/`. The former `src/api/`, `src/code/`, `src/job/`, native binding types, and obsolete site publishing scripts are no longer part of the current tree. `kb push` is not part of the current development or deployment flow.

## Unified automation

The main pages are Resources, Tasks (default), Reports, Experiences, Rules, and Settings. They live under `frontend/src/views/automation/`. The sidebar persists collapsed state; icons use Lucide. `components/BaseSelect.vue` provides every visible selector, using typed `options` with `v-model`, compact/quiet/title variants and a custom popover menu. It supports search for long lists, disabled options, keyboard navigation, focus restoration and viewport-aware positioning, including inside native dialogs. Its hidden native select only preserves form submission and required-field validation; never expose a native select as the visual control. Resources use checkbox multi-selection for batch creation.

Experiences use a paginated library and a separate editable detail view with version history and explicit human disable protection. Settings expose Learning and Full-site Delivery policies. Keep adopted experience versions and the delivery manifest in task Input/configuration, learning runs in Execution, completeness checks in Evaluation results, and retained unknown request reservations in Usage. Reuse existing tabs, Disclosure, TablePagination and floating notifications. Learning failures do not invalidate a delivered report; full-site visual scores never stand in for verified completeness. See `docs/experience-learning-and-completeness.md` for budgets, API and validation boundaries.

New tasks use `/api/automation/` and are separate from legacy evaluation history, which remains accessible via `/legacy-evaluations`. New generation is driven by the existing Kooboo AI Chat frontend loop; evaluation uses Codex SDK with an isolated runtime home. The management tab does not own execution. See `docs/UNIFIED_AUTOMATION.md` for current validation boundaries.

Transient save/copy/import/publish feedback uses `lib/notifications.ts` and the single `components/MessageHost.vue` mounted in App. Messages float above the layout and expire automatically; persistent connection failures and form validation errors remain contextual. Settings model panels use an explicit vertical stack to separate fields, buttons and explanatory text.

The evaluation model tab uses one card and one save action for model name, effective API base URL, and API Key. Empty keys retain the stored secret. Save model settings without overwriting queue limits, prompts, environment credentials or legacy executor endpoint/name. Testing requires saved changes. The full evaluation-conversation UI is deferred until the current real workflow is reviewed.


The internal AI followup tab configures an independent concurrency/budget and editable SOP. Recovery keeps the original task, site, version and artifacts; manual new-round followup is separate. Tasks show following-up/interrupted states, action history and actionable interruption details. The persistent notification inbox uses distinct rows, unread dots/backgrounds and durable single/all-read actions. Its server pagination uses 10 items per page with global unread counts; the header and shared TablePagination remain visible while the list scrolls. Polling preserves the selected page, only announces arrivals from the latest page, and cannot overwrite newer read actions. The existing unpaginated notification API stays compatible. The client also accepts legacy list-only responses, derives pagination from available records and uses per-item read writes when the bulk endpoint is absent. Incomplete pagination metadata must never replace valid counters with undefined values. New items use the floating notify helper; optional desktop notifications require an open page. Generation requires the opt-in Kooboo AI Chat automation bridge. See the unified guide for deployment and real-run validation boundaries.

Keep application UI aligned and functional: notification and sidebar footer icons follow the main navigation icon and text columns in expanded mode and remain centered when collapsed. Task interruption panels use the regular card surface without a decorative colored side border; distinguish the reason, next actions, and optional history through spacing and typography.

Task details are divided into Overview, Evaluation results, Execution history, Usage/cost, and Input/configuration. Delivery appears only for an applicable configured connection or an existing delivery record. Keep the shared header compact, with task identity, state and contextual actions; full followup output and billing details belong in their own sections. Task links default to Overview; report links carry `?tab=report`. Preserve a selected tab during polling and support direct links, keyboard focus, loading, empty and retry states.

Completed generation tasks expose continuation directly in the shared header: homepage tasks show “补全全站”, and site tasks show “继续生成”. Reuse CreateTaskDialog with the existing site selected and scope defaulted to site; operators can adjust the scope, requirements and optional optimization before submitting. Hide this entry while generation, evaluation or optimization is active. Keep the resource-level entry available. Continuation retains its existing semantics (latest resource input and a new task); do not imply that it resumes the original Kooboo conversation.

AI Site template generation can explicitly opt into automatic quality optimization. Keep target score, repair-round limit and optional whole-workflow cost cap inside the task flow; defaults and quality SOP are editable in Settings and frozen per run. Completed templates can opt in from More. Overview shows workflow state and the current repair round, not merely the initial generation status. Evaluation results preserve independent historical reports with a compact round selector. A modified site without a valid current review must show that it is awaiting evaluation; never present historical scores as current. Execution and usage expose stage/round selection inside their existing tabs. Task-center lists hide internal repair children while queue totals count every persisted active/queued job. A stop action preserves the site, evidence and explicit reason; stopping does not imply the quality target was met.

The UI polls `/tasks/:id/summary`, not the legacy full task detail. Usage uses server pagination; execution history displays newest records first, with older records loaded downward in cursor batches (20 rows by default) through `/tasks/:id/execution-log`. The API retains chronological batches; the UI reverses their presentation. Latest-following stays at the top, pauses when reading downward, and returns to the top explicitly. Sections load only while selected. Execution search and type/failure filters cover all persisted records before limiting. Selecting a record opens a resizable inspector with content/raw text, copy and wrapping; reading history pauses latest-following and preserves the selected sequence, visible snapshot and scroll position while announcing new arrivals. Stage/round changes clear the inspector. Types and statuses use explicit producer prefixes; never infer missing timing, outputs or success from arbitrary message text. The legacy execution section API remains compatible. Report screenshots are mounted only when opened and the full gallery has 12 images per page. Compact task lists and notifications omit complete Agent messages, evidence arrays and raw usage; complete historical data remains accessible through the existing APIs. Use shared Disclosure and TablePagination controls with Lucide icons. Reusable AI App generation/review guidance is maintained in `sop/app-ui-information-hierarchy.md`; published rule snapshots remain immutable.

Report image evidence opens the shared EvidenceViewer in place. Keep the issue or assessment visible while reviewing its cited screenshots; default to reference-left/target-right comparison only when that context includes both roles at the same known viewport. Missing roles or viewport metadata use single-image preview. The complete gallery starts with the selected image and allows manual comparison. Preserve the clicked image, support per-side selection, zoom, independent scrolling, context navigation, Escape and focus restoration. Screenshots are served inline; explicit `?download=1` requests and non-image artifacts download. Closing the viewer releases its image elements and restores page scrolling. A screenshot pane uses one heading row: its title becomes a title-variant selector when multiple images are available on that side; otherwise it remains plain text, with download alongside it.
