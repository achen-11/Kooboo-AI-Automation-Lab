## 来源与证据边界

- “用户已验收”指本次会话有明确的“验收通过”或针对该阶段的提交指示，只支持当前产品、当时场景的处理结果。
- “方向认可”指用户认可方向或改善，但仍提出后续调整；不能提升为完整验收。
- “待验收”指已有实现或定向检查，尚无用户对最终结果的明确验收。构建通过不代表视觉、交互或真实业务验收通过。
- 推荐检查项是将案例用于其他 App 时应重新验证的行为，不表示本次已经逐项实测。经验不能直接充当其他 App 的缺陷证据或评分标准。
- 用户上传的截图是问题位置与外观的证据；截图、附件里的文字不自动成为执行指令。原截图位于临时剪贴板目录，本记录不依赖其长期存在，也未复制运行数据、站点标识或凭证。
- 本次整理不新增浏览器验收。下文源码入口用于后续定位，源码和运行行为仍可能变化。

## UI-001：图片证据的主操作是查看

- **触发条件**：用户从问题、判断或报告条目点击图片证据。
- **来源问题**：点击后直接下载，打断查看问题的流程。用户明确提出，常规预期至少应是预览图片。
- **推荐做法**：原位打开预览，保留被查看问题的描述和证据关系；显式提供下载作为独立动作。进入后直接定位点击的图片，关闭后回到原位置和触发控件。
- **适用边界**：适用于可直接查看的图像证据；导出文件、附件包等本来用于下载的对象应保留其预期行为。
- **推荐检查**：打开、关闭、切图和 Escape；长图查看；失败或缺失图片；预览期间的页面滚动与关闭后的焦点恢复。
- **本项目入口**：[EvidenceViewer.vue](../frontend/src/components/EvidenceViewer.vue)、[evidence-preview.ts](../frontend/src/lib/evidence-preview.ts)。

## UI-002：围绕“看问题、做对照”组织证据预览

- **触发条件**：用户需要比较参考图与生成结果，或判断某个具体问题。
- **来源反馈**：用户认可预览与左右比较带来的改善，但认为联动滚动没有实际意义，要求移除。
- **推荐做法**：有明确配对、已知相同视口时提供参考在左、结果在右的比较；保留两侧独立选择、缩放和滚动。证据不成对时先提供单图查看，不猜测配对关系。
- **适用边界**：联动滚动只在内容位置存在可靠对应、能帮助判断时才有价值。本案例支持在当前场景移除，不支持“一切图片对照都禁止联动”。也不要求所有图片都默认占用双栏。
- **推荐检查**：点击的原图是否保留；参考 / 结果和视口是否正确；两侧长短不同、缺失一侧、窄屏时能否完成查看。
- **本项目入口**：[EvidenceViewer.vue](../frontend/src/components/EvidenceViewer.vue)、[EvidenceImagePane.vue](../frontend/src/components/EvidenceImagePane.vue)。

## UI-003：统一选择器的视觉与行为

- **触发条件**：同一站点有多个筛选、配置或图片选择入口，原生 select 的外观和布局与系统不一致。
- **来源要求**：用户要求封装一个全局通用选择器，并替换整站的可见原生 select。
- **推荐做法**：复用组件统一触发器、选项、选中与禁用状态、尺寸和菜单定位；按场景支持长列表搜索。保留键盘导航、可访问名称、关闭后焦点恢复及表单提交 / 必填语义。
- **适用边界**：这是本 Web 管理系统的组件决策，不能推广成所有 App 一律禁止原生选择器。组件内部为表单兼容保留隐藏 native select，不等于仍在展示原生控件。
- **推荐检查**：普通页、筛选工具栏、标题区域、弹窗内的选择器；菜单是否被裁切；长选项、空选项、搜索无结果和键盘选择。
- **本项目入口**：[BaseSelect.vue](../frontend/src/components/BaseSelect.vue)、[select.ts](../frontend/src/lib/select.ts)。

## UI-004：选择器可以承担标题，避免重复一份信息

- **触发条件**：区域标题与紧邻的选择器重复表达当前图片或当前对象。
- **来源反馈**：统一选择器完成后，用户指出原有内容已经成为重复信息，可以合并。
- **推荐做法**：多项可选时，将标题本身呈现为轻量选择器；只有一项时使用普通标题。下载等动作放在同一标题行，减少额外标签与描述。
- **适用边界**：合并前应确认二者表达同一对象。不要为了减少文字而删除必要的字段名称、单位或帮助信息。
- **推荐检查**：单项 / 多项切换后，当前对象仍明确，选择入口可发现，标题行不会重复或拥挤。
- **本项目入口**：[EvidenceImagePane.vue](../frontend/src/components/EvidenceImagePane.vue)、[BaseSelect.vue](../frontend/src/components/BaseSelect.vue)。

## UI-005：焦点样式应让人知道“正在编辑哪里”

- **触发条件**：输入框、选择器或复合输入控件获得焦点。
- **来源问题**：用户认为整站 input 的 selected / focus-visible 状态过于夸张，要求全局优化，随后明确验收。
- **推荐做法**：使用统一、适度的边框和浅阴影提示当前控件；复合输入框由整体容器表达焦点，避免内外多圈叠加。键盘操作仍须清楚看见焦点。
- **适用边界**：降低视觉强度不能变成移除焦点提示。焦点、文字选区、业务选中、校验错误是不同状态，应分别检查。
- **推荐检查**：鼠标点击与 Tab 导航；普通 input、textarea、搜索框、带按钮 / 单位的输入框、选择器和错误字段。
- **本项目入口**：[styles.css](../frontend/src/styles.css)、[BaseSelect.vue](../frontend/src/components/BaseSelect.vue)。

## UI-006：无法解释用途的元素值得重新审视

- **来源反馈**：用户指出某个元素始终不知道有什么意义，询问是否可以移除，并同意将小改动与下一任务一起提交。
- **推荐做法**：核对它是否支持真实决策或操作；与其他内容重复、没有有效动作且缺少明确用途时，可以删除。优先让布局和直接操作说明用途，避免增加一层说明来解释冗余。
- **证据限制**：当前文字上下文没有明确该元素的名称与位置，不能猜测并写成具体控件的删除规则。后续导入时保留为待核实案例，或在找回对应截图 / diff 后补全。
- **适用边界**：陌生或低频不代表无用；权限、安全、无障碍或特定工作流需要的内容应先确认实际用途。

## UI-007：通知应清楚分条，同时保持紧凑

- **触发条件**：通知浮层中连续显示多个事件。
- **来源问题与迭代**：初版条目界限不清；增强区分后用户明确认可，但要求条目再紧凑一些。
- **推荐做法**：通过轻边界、背景层次和稳定间距分隔条目；统一标题、对象、摘要、时间与操作的位置。压缩多余空白，避免每条通知都成为高大的展示卡片。
- **适用边界**：紧凑以可读和可操作为前提；无需增加更多徽章、描述或装饰来制造层次。
- **推荐检查**：短 / 长标题、多行摘要、大量通知和窄屏；能否快速辨认一条通知从哪里开始、在哪里结束。
- **本项目入口**：[AutomationNotifications.vue](../frontend/src/components/AutomationNotifications.vue)。

## UI-008：已读 / 未读是持久状态，不只是颜色

- **来源问题**：用户认为通知已读和未读状态没有做好。
- **推荐做法**：结合未读点、背景和明确文字区分；提供单条与全部已读操作，读取后持久保存。未读总数与当前页条数分开；后台轮询不能将刚标记已读的条目重新覆盖成未读。
- **适用边界**：已读只说明用户处理过通知，不代表任务成功或故障消失。历史异常仍保留来源，必要时说明后续状态。
- **推荐检查**：单条已读、全部已读、翻页、刷新、轮询并发，以及历史异常已恢复时的呈现。
- **本项目入口**：[AutomationNotifications.vue](../frontend/src/components/AutomationNotifications.vue)、[notice-inbox.ts](../frontend/src/lib/notice-inbox.ts)。

## UI-009：有分页控件不等于分页正确

- **来源问题与迭代**：用户先询问是否做了分页，随后指出底部总数和分页数据没有正确取得。视觉改进没有自动解决数据问题。
- **推荐做法**：分页请求、当前页、页数、总量和未读量形成一致契约。总量来自完整集合，不能用当前页条数代替；不完整响应不能把有效计数覆盖成 undefined。列表滚动时保留分页入口，刷新保留用户所在页。
- **适用边界**：小型有界列表可按规模选择本地分页；长列表使用服务端分页或有界增量加载。旧接口兼容应基于实际可得数据，不伪造未知总量。
- **推荐检查**：超过一页的数据、首尾页、空页、删除 / 已读后的页数变化、缺少元数据的响应，以及旧服务配新前端。
- **本项目入口**：[notice-inbox.ts](../frontend/src/lib/notice-inbox.ts)、[TablePagination.vue](../frontend/src/components/TablePagination.vue)。

## UI-010：次要按钮也需要被发现

- **来源问题**：通知已接近验收时，用户仍指出“标为已读”按钮太不明显。
- **推荐做法**：使用适度边框、对比色、图标及文字，让它明确具有可点击外观；保持比主要动作轻的视觉权重，并保留 hover、focus 和处理中状态。
- **适用边界**：不要求每个次要动作都变为高饱和实心主按钮。已读后的静态状态应与可点击按钮有区别。
- **推荐检查**：默认状态下是否能找到按钮，而非必须悬停才知道可以操作；未读 / 已读切换后是否仍清楚。
- **本项目入口**：[AutomationNotifications.vue](../frontend/src/components/AutomationNotifications.vue)。

## UI-011：表单间距与背景层次要成体系

- **来源问题**：系统设置中 checkbox 与相邻 input 距离过近，其他设置页签也有同类问题；跨环境交付容器背景与 input 背景重叠，输入轮廓难以识别。
- **推荐做法**：明确字段内部、字段之间、开关与其配置区之间的间距；通过可见边框或背景差区分输入框与父容器。抽取公共规则并检查同类设置页签。
- **适用边界**：不是所有 checkbox 都与所有字段拉大距离；控制某字段的开关仍需表达关联。背景差也应兼顾只读、禁用与错误状态。
- **推荐检查**：各设置页签、嵌套容器、长标签、窄屏，以及控件聚焦前后的轮廓。
- **本项目入口**：[SettingsView.vue](../frontend/src/views/automation/SettingsView.vue)、[styles.css](../frontend/src/styles.css)、[automation.css](../frontend/src/automation.css)。

## UI-012：用一致图标表达展开与收起

- **来源要求**：用户要求全局查找使用字符表示展开 / 收起的元素，统一替换为 icon。
- **推荐做法**：复用图标与 Disclosure 等公共组件，统一方向、尺寸、点击区和展开状态；图标按钮有可访问名称，控件表达 aria-expanded 等交互语义。
- **适用边界**：仅替换承担交互意义的字符，不机械修改正文、日志、代码或数学符号。不是只换字形而忽略可点击范围与状态。
- **推荐检查**：默认、展开、收起、键盘操作；同一页面和不同页面是否使用一致规则。
- **本项目入口**：[Disclosure.vue](../frontend/src/components/Disclosure.vue)、[TablePagination.vue](../frontend/src/components/TablePagination.vue)。

## UI-013：执行日志从“输出堆积”转成可检查记录

- **来源方向**：用户提出参考本机开源 dsh 的轨迹页面，并明确不要求完全一致，应结合本系统实际情况实施。
- **推荐做法**：列表展示时间、来源 / 类型、状态和摘要；选择记录后在检查区展示完整内容与原始信息。搜索、异常筛选、阶段 / 轮次选择、复制和换行控制服务于排查任务。
- **适用边界**：参考项目用于理解交互，不直接复制其对象模型和信息量。本系统有生成、评测、工具调用、跟进等实际差异；不要从任意文本猜测成功、耗时或缺失输出。
- **推荐检查**：不同来源记录、长文本、异常、阶段切换和窄屏；摘要不丢失语义，详细内容仍可追溯。
- **本项目入口**：[ExecutionLog.vue](../frontend/src/components/ExecutionLog.vue)、[execution-log.ts](../frontend/src/lib/execution-log.ts)。

## UI-014：日志顺序与刷新策略应配合阅读目标

- **来源反馈**：用户认为往上翻执行记录违和，建议倒序；后续认可并要求直接提交。
- **推荐做法**：监控场景最新记录在前，向下加载历史；用户读历史或检查某条记录时暂停自动跟随，保留选中项与滚动位置。新记录到达时提示，并提供明确回到最新的动作。
- **适用边界**：倒序适用于当前任务监控，不代表叙事、聊天、审计回放都应倒序。展示倒序不要求改写底层事件顺序；应以稳定序列 / 游标维护记录关系。
- **推荐检查**：同时间记录、连续新记录、加载更多、正在阅读时轮询、切换阶段与返回最新。
- **本项目入口**：[ExecutionLog.vue](../frontend/src/components/ExecutionLog.vue)、[execution-log.ts](../frontend/src/lib/execution-log.ts)。

## UI-015：重要指标直接进入列表，并表达含义

- **来源要求**：评测分数作为重要指标应独立成列；不同分数给予不同样式，让用户更快接收信息。
- **推荐做法**：将关键结果放在可扫描的固定列；保留 PC、移动端或业务等维度名称，不擅自平均。分数用文字数值和轻量样式共同表达，点击可进入对应报告。
- **本项目实现口径**：达到任务目标或配置阈值时为绿色；低于标准但未进入低分区时为橙色；低分为红色；无有效分数为灰色。低分边界受目标值约束。此口径是当前系统实现，不能照搬成所有 App 的固定评分规则。
- **适用边界**：未评测、无有效分数、未验证和零分不同。颜色应依赖实际业务标准，且不能成为唯一信息载体。
- **推荐检查**：阈值上下、null、0、多维度、历史结果和报告跳转归属；列表与详情是否一致。
- **本项目入口**：[TasksView.vue](../frontend/src/views/automation/TasksView.vue)、[task-list.ts](../frontend/src/lib/task-list.ts)。

## UI-016：快捷入口要有链接的外观与行为

- **来源问题**：生成的 URL 是常用快捷入口，却仅作为普通文字展示。
- **推荐做法**：用链接色和外部打开图标表达可访问性，长 URL 截断但可查看完整值；保留明确可点击区域及在新标签页打开的预期行为。
- **适用边界**：校验可访问协议，仅将有效 HTTP(S) 地址作为站点链接；无效或缺失地址按实际状态显示。外部打开的安全属性随实现保留。
- **推荐检查**：长地址、空地址、无效协议、点击是否误触整行，以及新标签页行为。
- **本项目入口**：[TasksView.vue](../frontend/src/views/automation/TasksView.vue)、[task-list.ts](../frontend/src/lib/task-list.ts)。

## UI-017：不要把历史结果消失误判为“没有分数”

- **来源经过**：用户先指出列表最后一条实际有分数；随后发现同一站点又新起了一次任务，范围从仅首页变成全站。首轮修复后用户仍反馈没有生效。
- **问题含义**：必须区分原任务、后续任务、当前站点结果和历史评测结果。新任务的范围不等于旧任务被修改；站点已更新也不应导致旧任务已有报告在历史列表中消失。
- **推荐做法**：按任务关联、站点身份、范围和轮次定位报告；历史结果可展示，但明确其时效，点击进入确切报告。新任务尚未评测时仍如实显示待评测，不能借用旧分数制造已通过的印象。
- **交付经验**：源码改动不等于正在运行的服务已更新。应核对实际接口响应、精简摘要、前后端版本兼容及实际提供的前端资源。当前实现对可见行缺失的已完成报告按需补取摘要，并核对身份和版本；这只是适配当前数据契约的方法，不应推广为所有列表一律逐行请求。
- **适用边界**：不能随意取“同站点最新一次”替代明确关联的报告。保留正在运行的任务，不为让 UI 修复生效而随意重启工作进程。
- **推荐检查**：同站点多任务、首页与全站并存、历史 / 当前结果、旧摘要缺少分数、轮询更新、缓存过期及精确报告跳转。
- **本项目入口**：[task-list.ts](../frontend/src/lib/task-list.ts)、[TasksView.vue](../frontend/src/views/automation/TasksView.vue)、[task-presentation.ts](../shared/task-presentation.ts)、[api.ts](../server/automation/api.ts)。

## UI-018：枚举样式表达类别，帮助快速扫读

- **来源要求**：任务列表“类型”“范围”都是枚举，不同类型可赋予不同样式，提高信息接收速度。
- **推荐做法**：用轻量图标标签区分类别，同时保留文字；同列尺寸、间距和形态一致，避免新增一层解释。
- **本项目当前方案**：生成为蓝色、评测为紫色；仅首页为灰色、全站为青色；配合对应图标与浅背景。
- **适用边界**：这是类别编码，不是好坏判断。不要让用户将全站误解为通过、仅首页误解为禁用；具体配色不是所有 App 必须遵循的规则。
- **推荐检查**：多种枚举混排、文字与图标对应、窄列、视觉权重是否压过状态或关键分数。此轮仅构建通过，仍待用户视觉验收。
- **本项目入口**：[TasksView.vue](../frontend/src/views/automation/TasksView.vue)。

## UI-019：UI 问题也可能来自真实数据或运行错误

- **来源反馈**：用户在通知优化阶段同时指出“系统设置 → 费用”似乎有报错；相关修改阶段后来验收通过。
- **推荐做法**：遇到页面报错，先核对真实请求、响应和组件状态。局部数据加载失败应有明确反馈及恢复入口；不能只调整样式或隐藏异常来完成视觉验收。
- **证据限制**：会话文字没有提供足以确认的具体错误与根因，本记录不补造原因，也不将其他后续费用功能变化视为这次修复。
- **适用边界**：可作为“视觉检查要覆盖运行状态”的候选经验；具体技术修复需回溯对应差异或重现问题后再沉淀。
- **本项目定位入口**：[BillingSettings.vue](../frontend/src/components/BillingSettings.vue)。

## UI-020：资料包应保留目录语义，并提供查看入口

- **来源问题**：资源库 → 资源详情 → 资料与输入将所有附件平铺，重复展示完整路径，无法直观看出目录关系；用户要求优化文件夹识别、展示和简单预览。
- **推荐做法**：从已保存的相对路径构建目录层级，文件夹可折叠、显示下属文件数量，文件按类型使用图标。目录与文件预览相邻；搜索保留匹配项的祖先路径，避免丢失同名文件的上下文。
- **本项目当前方案**：左侧目录、右侧预览，窄屏上下排列；优先选择 README，只加载当前文件。图片支持适应区域 / 原始尺寸；Markdown 默认以文档排版显示，可切换源码，其他文本和代码以纯文本预览。长文本明确显示截断范围；下载是独立动作，其他格式明确提示可下载查看。
- **后续反馈**：用户认可目录与预览体验，并提出 Markdown 应渲染语法。文档阅读应呈现标题、列表、引用、表格与代码块的层次，文件目录不能替代内容阅读体验。当前补充支持资料内相对文件链接、按需显示本地图片，以及不改变应用路由的文内锚点；禁止执行上传的 HTML。这些补充仍待用户验收。
- **适用边界**：平铺列表仍适用于少量无层级文件；没有真实目录信息时不凭文件名猜分组。简单预览不等于支持所有文档格式，也不应把上传的 HTML 当页面执行。切换文件时取消旧请求，避免串位，并限制预览体积。
- **推荐检查**：多层目录、跨目录同名文件、收起 / 展开、搜索及清空、长图和透明 SVG、文本与空文件、快速切换、缺失文件、超长文本和不支持的格式。当前未做浏览器视觉验收。
- **本项目入口**：[MaterialBrowser.vue](../frontend/src/components/MaterialBrowser.vue)、[MaterialTree.vue](../frontend/src/components/MaterialTree.vue)、[material-browser.ts](../frontend/src/lib/material-browser.ts)。

## UI-021：详情页头部应给主要内容让出空间

- **来源问题**：资源详情的返回入口、标题、场景 / 版本和页签分成多层，用户指出头部几乎占首屏四分之一，可压缩成一至两行。
- **推荐做法**：把返回、名称和主要操作放在第一行，页签与必要元信息放在第二行；降低标题字号与多层间距。长名称可截断并保留完整值提示，窄屏允许合理换行。
- **适用边界**：这是以文件、日志、表格等内容为核心的管理详情页经验；不是要求所有页面都用小标题，或机械限制所有屏幕下只能两行。必要身份、版本与主要动作仍需可找到。
- **推荐检查**：常见桌面首屏可见的实际内容是否增加；长名称、多操作、窄屏和键盘焦点是否被裁切；不要只用缩小字体解决布局问题。本次未做浏览器视觉验收。
- **本项目入口**：[ResourcesView.vue](../frontend/src/views/automation/ResourcesView.vue)。

## UI-022：主要内容优先，辅助信息不应持续占据首屏

- **来源问题**：压缩资源详情头部后，用户仍指出内容站 / 参考站、文字说明占用太多空间，明确期望主区域是文件资料库。链接缩为标签后，用户补充仍应展示实际链接，只需安排在合适的位置。
- **推荐做法**：以文件浏览区作为主界面，将已配置站点收为工具栏中的紧凑链接，同时展示站点角色与实际地址；长地址省略、悬停显示完整 URL，相同地址合并。精简占比时保留用户识别目的地所需的信息。说明与外部来源按需展开。缺少链接或说明时不占一块区域反复展示“未提供”“暂无说明”。去掉文件库外层重复容器与大留白，让目录和预览使用桌面端剩余高度。
- **适用边界**：适用于资料浏览是当前主要任务的页面。对 URL 或说明本身承担主要决策信息的任务，应保留其可见性；折叠后入口仍需明确，不能删除真实输入。长说明在展开后有自己的滚动边界，窄屏仍允许自然排列。
- **推荐检查**：仅参考站、内容与参考同址、无链接 / 无说明、长说明和外部来源；展开与收起、窄屏、文件搜索及阅读区域是否合理。不能仅缩小页面标题就认为首屏信息层级已经优化完毕。
- **本项目入口**：[ResourcesView.vue](../frontend/src/views/automation/ResourcesView.vue)、[MaterialBrowser.vue](../frontend/src/components/MaterialBrowser.vue)。
