## 恢复的模板流程

开始检查时，新流程模块和 Gemini 前端组件已在工作区，但 API 注册、任务绑定、生成/评测分流与规则页等接入仍在 `stash@{0}`。只恢复相关接入，并合并当前 v0.6.4 的站点名称恢复、实时对比、活动执行检测和强制恢复行为；原 stash 保留。

新建模板生成任务固定检查集版本。参考分析先建立页面、语义区块、双端约束和交付清单；不完整来源阻止创建目标站。生成后以当前证据逐项记录 passed / failed / unverified / not-applicable。问题只能经独立复验关闭，前端不能手工勾为通过。旧任务不升级、不改写历史分数；改变来源或范围应新建任务。

检查集不是一项一个模型会话：同一轮共享采集、按区块批量判断、统一校验。局部复用保留旧证据所属任务和修订，不能把旧图标为当前实测。

## 设计师材料的拆分

来源：用户 Downloads 下的 `AI网页生成规范.md`、`AI-Prompt.txt`。后者主要是前者第 16 节的精简版，不重复叠加整份提示词。

基础 prompt 与结构化检查定义集中在 `shared/template-design.ts`。分析和生成收到相同原则，逐项结论由独立评测产生，替代原材料中的“让生成 AI 自报 pass/fail”。

初始检查集由原 8 项区块检查加 6 组设计规范构成。当前安装已保留原 v1，并发布 14 项 v2 作为后续任务的默认版本；原任务仍绑定旧版本。准确发布内容见 [template-designer-checklist-v2.json](./template-designer-checklist-v2.json)。源码不会自动覆盖其他安装的已发布版本；规则页编辑时可用“加入设计规范”补齐缺失组，再审阅、发布新版本。已有同 ID 自定义内容或禁用状态不被覆盖。

这些检查不等于已实现 24 项确定性检测器。字号、对比度等精确数值需要测量/源码或实现证据；截图不能证明精确比值、键盘流程和动效行为。保留“不适用”的具体依据；缺证据不能勾通过。

### 不直接全局强制的规则

- H03 的所有桌面站都吸顶、禁止汉堡菜单：改为按参考与明确需求冻结，仍要保证导航可访问、不遮挡。
- H07/H11 的固定卡片数/三列价格：沿用模板实际数量与版式，修正无意空洞，不为凑数编造事实。
- H08 的全站 section 统一 96/120/160：采用一致 tokens 和模板节奏，不抹平有意的疏密变化。
- H05 的固定行数、H02 的绝对坐标：结合语言与实际视口；正常断行可声明例外。
- H14 的“页脚≥13px”和“版权12px”：正文链接≥13px、版权允许12px。
- H22 的占位文案限制不覆盖模板要求的 `imagePlaceholder`。
- §14.2 要求 1440 / 1280 / 390 三档；当前自动模板流程仍是 desktop/mobile 两种视口，不能宣称已做三档验收。

## Kooboo 截图与图片处理

本地 Puppeteer 与远端截图服务源码共用有界滚动脚本：分段滚动触发懒加载，跟随高度增长，到稳定底部后有界等待图片/字体，再回顶部截图。超出时间、步数或高度限制会失败；本地预热失败不会转向旧远端服务返回未预热图。远端服务必须更新部署才具有新行为。

新增 `process_image`，从当前站媒体库读取截图，以源像素坐标 crop 或 slice，不缩放、不覆盖原图。切片默认高900、重叠80、每次最多6张，可用 nextOffset 继续；工具最大每次12张。每片保存PNG并返回坐标与媒体引用，再通过 `read_image` 看图。

Lab 已有逐屏采集保持原路径；Kooboo 的 fullPage→切片用于生成侧/单独调用截图工具，不能替代 Lab 对来源、修订和证据完整性的校验。滚动预热也不能保证虚拟列表和滚动驱动动画在 fullPage 中全部呈现，仍需人工实测。

## 批量开始前

先用少量有代表性的站完成完整真实流程：参考分析→生成→独立检查→至少一次修复复验，核对误报、漏检、耗时和费用，再逐步扩大批次。仅测试与构建不能证明 200 个站点可以直接无人值守完成。用户已授权截图测试；本轮未运行真实站点生成与完整模型闭环。
